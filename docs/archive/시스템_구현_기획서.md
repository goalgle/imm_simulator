## 문서의 목적

아이디어 기획서가 **"무엇을 만들 것인가(What)"** 를 정의한다면,
이 문서는 **"어떻게 만들 것인가(How)"** 를 정의한다.

| 구분 | 아이디어 기획서 | 시스템 구현 기획서 (본 문서) |
|---|---|---|
| 관심사 | 게임 컨셉, 메커닉, 콘텐츠 | 렌더링, 데이터 모델, 아키텍처 |
| 변경 주체 | 디자인 결정 시 | 기술 결정 시 |
| 독자 | 디자이너 / 본인 | 구현자 / 본인 |

아이디어 기획서의 항목 중 **구현 가능성/성능/일관성에 영향을 주는 부분**만 본 문서에서 다룬다.

## 1. 핵심 기술 결정

### 1.1 게임 엔진: Phaser 3

확정. 아이디어 기획서 결정 사항 유지.

### 1.2 렌더링 전략

**원칙**: 메인 오브젝트(세포/세균/바이러스)는 **함수 평가 결과**여야 한다. 비트맵 스프라이트나 미리 그려둔 polygon 데이터로 표현하지 않는다.

#### 후보 비교

| 방식 | 어떻게 | 100개 기준 성능 | 함수 적합성 | 학습 부담 |
|---|---|---|---|---|
| A. `Graphics` + path redraw | 매 프레임 `lineTo` 60점 | ❌ 약 50개 한계 | ⭕ polygon 근사 | 낮음 |
| B. `Mesh` + 동적 vertex | CPU 계산 후 vertex buffer 갱신 | ⭕ 200~300개 | ⭕ polygon 근사 | 중간 |
| C. Custom Vertex Shader | GPU에서 `r(θ,t)` 계산 | ⭐ 1000개+ | ⭕ GPU 평가 | 높음 |
| D. Fragment Shader (SDF) | 픽셀 단위 implicit field 평가 | ⭐ 수백 개 | ⭐⭐ 함수 = 형태 | 중간 |

#### 채택안: **per-cell Graphics + 동적 polygon redraw** (B 방식의 단순 변형)

```
Phase 1 (MVP):  Phaser.GameObjects.Graphics × N  (per-cell, fillPoints 매 프레임)
                ↓ 게임플레이 검증
Phase 2 (필요시): D 방식 (Fragment Shader / SDF) 로 교체 — 어댑터 교체로 처리
```

**근거 (M0 검증 결과)**:

> 측정 환경: Apple Silicon Mac 추정, Phaser 3.80.1 WebGL 렌더러, 단일 기기 측정.
> 보강 필요: Chrome CPU throttling을 사용할 수 있는 환경에서 약한 기기 시뮬레이션 재측정.

| 시나리오 | FPS 결과 | 비고 |
|---|---|---|
| 5000개 / 64 verts / homo / per-cell | 60 (GO) | baseline |
| 5000개 / 96 verts / homo / per-cell | 30~60 (CONDITIONAL) | vertex 정밀도 한계점 |
| 5000개 / 64 verts / mixed(7종) / per-cell | ≈ homo와 동일 | 색 다양성 영향 미미 |
| color-grouped 정렬 | random/y-sorted 대비 미세 우위 | 효과 작음 |

**해석**: 워크로드는 **CPU-bound** (sin × 3 × verts × cells ≈ 매 프레임 수십만 호출). GPU/색 batch 비용은 무시 가능 수준.

**결론**:
- **MVP 100~500개 목표는 광범위한 안전 마진**으로 통과 (Apple Silicon 기준 50배 이상 여유).
- 색별 정렬 같은 batch 최적화는 **불필요** — 코드 단순성 우선.
- 진짜 최적화 포인트는 CPU 측 → **`sin()` 룩업 테이블, vertex 객체 재사용** 이 효과 클 가능성. M1에서 함께 구현.
- D 방식(SDF)은 **현 시점 도입하지 않음**. 본 게임 진행 중 한계 도달 시에만 어댑터 교체로 처리.
- B(Mesh) 방식보다 **Graphics + fillPoints가 더 단순**하고 결과 동일 → Mesh API 학습 부담 제거.

#### 렌더 어댑터 인터페이스 (양 방식 공통)

```typescript
interface CellRenderer {
  create(dna: DNA, position: Vec2): RenderHandle;
  update(handle: RenderHandle, dna: DNA, tempState: TempState, t: number): void;
  destroy(handle: RenderHandle): void;
}

// MeshCellRenderer: B 방식 구현체
// SDFCellRenderer:  D 방식 구현체 (Phase 2)
```

본 게임 로직(`WhiteCell`, `Bacteria` 등)은 **인터페이스만 의존**한다. 렌더러 교체 시 게임 로직 변경 없음.

### 1.3 충돌 모델

- **시각**: 함수 기반 변형 형태 (Mesh/SDF)
- **물리**: `baseRadius` 기반 **고정 원형 hitbox** (Phaser Arcade Physics 그대로 사용)
- **근거**: 변형되는 외곽선 충돌은 비용이 크고, 게임플레이상 정확도 요구 낮음. 시각 ≠ 물리 분리는 표준 관행.

### 1.4 좌표/시간 단위

- 좌표: Phaser 기본 (px, 좌상단 0,0)
- 시간: 초 단위 float (`t`, `dt`)
- 룩업 테이블 해상도: **0.0167s (60Hz)** — 아이디어 기획서의 0.1s(10Hz)는 시각적 떨림 우려로 상향 조정

### 1.5 입체감 렌더 스타일 (Session 14 도입)

§1.2 의 per-cell Graphics 위에 layered fill 로 입체감 부여. **vertex 평가는 1회**, 추가 비용은 fill 호출 ×3~4 + 점 곱셈 정도. shock/combat/life 시각 채널(§2.5)과 호환.

`src/render/GraphicsCellRenderer.ts` 상단 `RENDERER_TYPE: 'A' | 'B' | 'C'` 상수 변경 후 빌드. 런타임 토글은 페이즈 2 게임 룰과 함께 결정 예정 (현재 미정 — 미니게임 컨텐츠 정해진 후 자연스럽게 인터페이스가 드러남).

#### TYPE A — 매끈한 구체 음영 (의학 일러스트 톤, 기본)

```
1) Rim       : polygon 원본 + 어두운 색 (외곽 림)
2) Body      : polygon ×0.88 + 본체 색
3) Highlight : polygon ×0.55 + 좌상단 오프셋(base ×-0.1) + 밝은 색 α 0.5
4) Specular  : 작은 흰 점 (base ×0.12)
```

색은 base HSL 의 명도/채도 조정으로 파생. life=0 (시체) 시 채도 0 → 자동 회색 톤.

#### TYPE B — 발광/젖은 (네온/생체)

```
1) Halo       : polygon ×1.10 + 밝은 색 α 0.4 (외곽 번짐)
2) Body       : polygon ×0.95 + 채도 +15
3) InnerGlow  : polygon ×0.60 + 좌상단 오프셋 + 명도 +35 + α 0.65
4) Specular   : 큰 흰 점 (base ×0.18) + α 0.85
```

전체적으로 채도/명도 ↑ → 자기 색이 발산되는 인상. PostFX glow 와 자연스럽게 합성.

#### TYPE C — 만화풍 (두꺼운 외곽선 + 평면 톤)

```
1) Body      : polygon 원본 + flat 본체 (스케일 1.0)
2) CellShade : polygon ×0.55 + 좌상단 + flat 밝은 톤 (α 1.0, 그라데이션 X)
3) Outline   : strokePoints, 두께 base ×0.10 (최소 2px), 채도/명도 ↓ 잉크 톤
- specular 없음
```

`Phaser.GameObjects.Graphics.lineStyle + strokePoints` 로 진짜 외곽선 스트로크. 평면 톤 유지가 핵심이라 알파 1.0.

#### 영웅급 PostFX Glow (모든 타입 공통)

`isHeroDna(dna)` (커맨더 / T세포 / 슈퍼호중구) 인 경우, handle 생성 시 `gfx.postFX.addGlow(color, outer=4, inner=0, false, quality=0.1, distance=14)` 적용. 색은 DNA hue + 채도/명도 가산으로 파생 → 자기 색이 발산되는 영웅 표시.

**비용**: PostFX 는 인스턴스당 별도 렌더 타깃 → batch 깨짐. 영웅급은 소수라 OK. 슈퍼호중구가 누적되면 fps 영향 모니터링 필요.

**TYPE_C 와의 시각 충돌 가능성**: 만화 외곽선 + 외부 glow 는 시각 톤이 안 맞을 수 있음 — 거슬리면 RENDERER_TYPE 별 분기 추가 (한 줄).

| **백혈구** | 호중구, T세포, NK ... | ✅ | ✅ | ✅ 받음 | — |

| **고름(Pus)** | 백혈구 잔해 | ❌ | ❌ | TBD | ❌ |

**영양분(Nutrient) 명세**:
- 화면 내 절대값 고정 슬롯 (시작값 **40**)
- 무작위 위치, 정지 (이동 없음)

- 세균이 흡수 시 즉시 비활성화 + **4초 후** 다른 무작위 위치에 부활 (총수 보존, 자원 압박)
- 백혈구는 충돌 없이 통과 — 단, **통과 시 약간의 시각 효과 예정** (구체 디자인 TODO)
- 충격파 시스템에 의해 움직이지 않음 (`ShockwaveSystem.applyToCells` 적용 대상에서 제외)
- 시각: 단순한 작은 점/원 (함수 기반 형태 X — 생명체 아니므로 다른 코드 경로)

**시체(Corpse) 명세** (M3.4 도입):
- 백혈구/세균이 hp=0 도달 시 같은 인스턴스가 시체 모드로 전환 (별도 클래스 없음 — `isDead()` 분기)
- 시각: **채도 0 (회색) + 형태 떨림 정지 + 최소 크기(MIN_SCALE=0.5) 유지**
- 행동/충돌/임펄스 모두 정지: drives senses 후보 X, ShockwaveSystem 임펄스 X, ContactSystem 데미지 X
- **분리력 제외 → 겹침 허용**
- **중력만 작용**: vy += GRAVITY × dt, 화면 바닥(큰 Y) 도달 시 vy=0 침전
- 시체 페이드아웃/대식세포 흡수는 M4 에서 (현재는 영원히 누적 — 검수 후 결정)

### 2.4 세균 행동 모델

세균의 행동 동기 = **생존(영양분 흡수) + 자가증식(분열)**.

#### 2.4.1 1단계 — 단순 추적 (M2.1)

```
1. 가장 가까운 영양분 탐색
2. 그 영양분으로 이동 (속도 = DNA.behavior.speed)
3. 도달 시 흡수 → 흡수 카운터 +1, 영양분 풀에서 1개 소비/재생성
4. 흡수 카운터가 분열 임계치 N=3 도달 시 분열 시작
5. 0.5초간 시각적으로 부풀음 → 자기 복제 1마리, 카운터 0
```

이 단계에선 동족/포식자 인식 없음. 세균은 영양분만 본다.

#### 2.4.2 2단계 — drives 모델 + 관성 (M2.2 ✅ 완료)

**결정 모델**: 부드러운 우선순위 (가중 벡터 합 + 거리 기반 활성도).

**DNA 스키마 확장 (실제 구현)**:
```typescript
DNA.behavior.turnRate: number;  // 1/sec — 클수록 빠른 방향 전환 (관성 ↔ 즉시)
DNA.drives = {
  avoidPredator: { weight, triggerRadius };  // 1순위 (큰 weight)
  seekNutrient:  { weight };                  // 2순위
  spaceAlly:     { weight, comfortRadius };   // 3순위 (동족 회피)
  seekAlly:      { weight };                  // 군집형 종 용도 (다른 종에서 활성)
};
```

배열이 아닌 **객체**로 둔 이유: 모든 필드가 숫자 → 바이러스 변이가 산술 연산 (`weight *= 1.3`) 으로 일관 처리. 새 종 = 같은 구조에서 값만 다름.

**행동 합성**:
1. 각 drive 평가 → (단위 방향 벡터, 활성도 0~1)
2. 가중 합: `Σ dir × activation × weight`
3. 정규화 → 단위 방향
4. desired velocity = 단위 방향 × `behavior.speed`
5. 부드러운 가속: `v += (desired_v - v) × (1 - exp(-turnRate × dt))`

**활성도 규칙**:
- `avoidPredator`: 가장 가까운 포식자가 `triggerRadius` 안에 있을 때만, 가까울수록 ↑
- `seekNutrient`: 영양분이 있으면 항상 1
- `spaceAlly`: 가장 가까운 동족이 `comfortRadius` 안에 있을 때만, 가까울수록 ↑
- `seekAlly`: 동족이 있으면 항상 1

**호중구 영향**: 모든 drive weight=0, turnRate=0 (자체 추진하지 않으므로 무영향). 충격파로만 이동.

#### 분리력 (M2.2 ✅ 완료)

DNA 형질이 아닌 **물리적 처리**. 같은 종족 쌍별 검사, 거리 < (r1+r2+padding) 이면 멀어지는 가속도 누적.

- 위치: `src/domain/separation.ts` (순수 함수)
- 매 프레임 BloodScene 에서 두 번 호출 (백혈구끼리, 세균끼리)
- 다른 종족 간 분리는 M3 충돌 시스템에서 별도 처리
- 파라미터: `padding=4, strength=400 px/s²` (조정 가능)

#### 세균 DNA 프리셋 (실제 구현, M2.2 시점)

```typescript
const BACTERIA_A: DNA = {
  shape: { base: 18, w1: {A:0.20,n:5,omega:1.5}, w2: {A:0.15,n:7,omega:2.0}, w3: {A:0.10,n:9,omega:2.5} },
  color: { h: 0, s: 0, l: 30 },
  behavior: { target: 0, speed: 30, contact: 0, turnRate: 3.0 },
  drives: {
    avoidPredator: { weight: 1.0, triggerRadius: 180 },
    seekNutrient:  { weight: 0.6 },
    spaceAlly:     { weight: 0.3, comfortRadius: 50 },
    seekAlly:      { weight: 0 },
  },
  meta: { recovery: 0.3, divide: 0 },
};
```

**시작 마리 수**: 3.
**미래 다종**: `BACTERIA_B`, `BACTERIA_C` ... (예: 군집형은 `seekAlly` weight 활성, `avoidPredator` 약화 등).

**구현 위치 (실제)**:
- `src/entities/Bacteria.ts` — 세균 엔티티 (DNA + 흡수 카운터 + mitosis)
- `src/entities/Nutrient.ts` — 영양분 (단순 데이터)
- `src/render/NutrientRenderer.ts` — 영양분 점 batch
- `src/systems/NutrientSystem.ts` — 풀 (active/inactive + 4초 부활 지연)
- `src/systems/BacteriaBehaviorSystem.ts` — drives 호출 + 관성 + 분열 자식 생성
- `src/domain/drives.ts` — drive 평가 함수 (Phaser 의존 0)
- `src/domain/separation.ts` — 분리력 (Phaser 의존 0)

**렌더 인터페이스 변경**: 분열 애니메이션을 위해 `CellRenderHandle.setScale(scale)` 추가.

#### 2.4.3 3단계 — 커맨더 + 팀 + 공격 모드 (M5.1~5.3 ✅ 완료)

세균 종족에 **지휘관(BACTERIA_COMMANDER)** 도입. 일반 세균은 무리 결정에 동참하여 단순한 추격 → 그룹 의사결정으로 진화.

**DNA 스키마 확장**:
```typescript
DNA.command = {
  visionRange: number;        // 호중구를 멀리서 인지하는 시야 (팀 모드 결정용)
  commandRange: number;       // 멤버 영입/유지 거리
  visionGrowth: number;       // 영양분 흡수마다 시야 +
  commandGrowth: number;      // 영양분 흡수마다 지휘범위 +
  baseTeamSize: number;       // 0 = 지휘관 아님, ≥1 = 지휘관
  teamSizeStep: number;       // 몇 레벨마다 팀원 +1
  levelUpAbsorbCount: number; // 영양분 N개 = 1 레벨업
};
DNA.drives.followCommander: { weight }; // 멤버가 지휘범위 밖에서 끌려옴
```

**시야 분리** (중요):
- **회피 시야** = `drives.avoidPredator.triggerRadius` (커맨더도 일반과 같음 = 180px) — 가까이 와야 도주
- **공격 결정 시야** = `command.visionRange` (커맨더 540, 일반 0) — 팀 모드 결정용 정보 채널

두 시야 분리로 **시야는 넓되 평소 영양분 추구를 방해하지 않음**.

**커맨더 행동 분기**:
- 영양분 흡수 → 시야/지휘범위 ↑ + 레벨업 (분열 X — 일반 세균과 다름)
- 호중구 처치 보상 → 영양분 1개 흡수와 동등 효과 (팀 전체 적용)
- 매 3레벨마다 `currentMaxTeamSize +1`

**팀 시스템 (TeamSystem)**:
- 영입: 지휘범위 안 무소속 일반 세균 자동 영입 (max 도달까지)
- 탈퇴: 지휘범위 × 1.5 이상 멀어지면 자동
- 모드 결정 (매 프레임):
  - 멤버 < `baseTeamSize` → 강제 `defensive` ("팀으로 이루어진" 조건 미달)
  - 시야 안 표적 + 팀 총 HP > target HP × **1.5** → `aggressive` + `attackTarget`
  - 그 외 → `defensive`
- 사망 시: 커맨더 죽으면 팀 해체, 멤버는 무소속 복귀

**표적 우선순위** (M7 추가, `priorityOf`):
1. **BCELL** — 정지/약체 + 항체 위협 차단

### 2.5 시각 채널 분리 (M3.4 도입)

엔티티의 일시 자극을 **3채널** 로 구분하여 렌더러가 합성. 각 채널이 다른 시각 특징을 가져 사용자가 자극의 종류를 구분 가능.

```typescript
type VisualState = {
  shock: number;   // 0~1, 충격파 임펄스
  combat: number;  // 0~1, 적과 접촉
  life: number;    // 0~1, 1=살아있음, 0=완전 사망
};
```

| 채널 | 트리거 | 시각 효과 |
|---|---|---|
| **shock** | 충격파 임펄스 (사용자 클릭/탭) | 채도 ↑ + 명도 ↓ + 떨림 진폭 ↑ — "자기 색이 진해짐" |
| **combat** | 호중구 ↔ 세균 접촉 | hue 를 빨강(0°)으로 lerp + 채도 ↑ + 떨림 ↑ — "다른 색이 됨" |
| **life** | hp=0 도달 (사망) | 채도 ×0 (회색) + ampBoost ×0 (떨림 정지) |

세 채널이 동시 작용 가능 (충격파 맞으면서 세균과 접촉 중인 호중구는 "약간 빨개진 진한 분홍이 떨림"). 합성 공식은 `GraphicsCellRenderer` 내부:

```
hue   = baseH + (RED - baseH) × combat × 0.6
sat   = (baseS + 15·shock + 20·combat) × life
light = baseL - 25·shock
amp   = (1 + 0.5·shock + 0.4·combat) × life
```

**확장 여지**: `tempState` (M5+) 같은 다른 자극도 새 채널로 추가 가능. 인터페이스만 늘리면 됨.

### 2.6 호중구 재생산 (M5.4 — 대식세포 + 슈퍼 호중구)

**대식세포(MACROPHAGE) 명세**:

#### 2.6.1 호중구 자기 융합 (M7 추가)

슈퍼 호중구 생산의 **두 번째 경로** — 외부 자원(대식세포 점수) 외에 내부 협력으로도 진화. 약한 동료를 살리지 못해도 "흡수해서 더 강한 호중구로 환원" 하는 면역 자가 회복 메커니즘.

**행동 분기 (NEUTROPHIL 한정)**:
- 자기 약함 (`hpRatio < WEAK_HP_THRESHOLD = 0.25`): 가장 가까운 강한 동료 추적 (세균보다 우선) — 흡수 받기 위해
- 자기 강함 + 약한 동료 있음: 약한 동료 추적 (세균보다 우선) — 흡수 시도
- 그 외: 기존 (세균 추적)

이 분기는 drives 변경 없이 `WhiteCellBehaviorSystem` 의 `senses.nearestPrey` 동적 결정으로 구현 (`findAllyTarget`).

**흡수 조건**:
- 둘 다 살아있는 NEUTROPHIL (NK_CELL / NEUTROPHIL_SUPER 는 DNA 동등성 비교로 제외)
- 거리 < `r1 + r2 + FUSION_PADDING(2)`
- 한 쪽만 약함 (둘 다 약하거나 둘 다 강하면 흡수 X)

**처리**:
- 약한 호중구 → `isAbsorbed=true` (시체 X, 즉시 소멸)
- 강한 호중구 → `mergeCounter += 1`
- `mergeCounter ≥ 2` → 자기 isAbsorbed=true + 같은 자리에 NEUTROPHIL_SUPER spawn

**파라미터**:
- `WEAK_HP_THRESHOLD = 0.25` (export const, `entities/WhiteCell.ts`)
- `FUSION_PADDING = 2` px (`systems/WhiteCellBehaviorSystem.ts`)
- `FUSION_THRESHOLD = 2` (흡수 횟수)

**구현 위치**:
- `entities/WhiteCell.ts` — `mergeCounter`, `isWeak()` 헬퍼, `WEAK_HP_THRESHOLD` 상수
- `systems/WhiteCellBehaviorSystem.ts` — `findAllyTarget()`, `processFusion()`, 매 프레임 update 끝에 호출

**시뮬레이션 균형 효과**:
- 세균이 약한 호중구를 자주 만들수록 → 융합 활성 → 슈퍼 호중구 자가 생성 → 면역 반격 강화
- 대식세포 경로(외부 자원)와 융합 경로(내부 협력) 가 동시 작동 — 두 가지 회복 채널

### 2.7 커맨더 진화 (M7)

커맨더가 사망해도 세균 생태계가 영구 정지되지 않도록 **자동 진화** 메커니즘.

```
커맨더 사망
  ↓ TeamSystem.commanderDeathTimes 에 시각 기록 + 팀 즉시 해체
  ↓ 10초 경과
  ↓ TeamSystem.consumeExpiredDeathRecords 가 만료 record 반환
  ↓ BloodScene.evolveCommanders 가 살아있는 일반 세균 1마리 무작위 선택
  ↓ 그 자리에서 즉시 BACTERIA_COMMANDER 로 변환 (기존 세균 isAbsorbed=true 로 정리)
  ↓ 새 커맨더가 다시 멤버 영입 시작
```

**조건/예외**:
- 진화 대기 중에 일반 세균이 모두 사라지면 진화 무산 (record 는 이미 소비됨, 다음 사망 시 재시도 없음)
- 다중 커맨더 (현재 게임에 1마리뿐이지만) 라면 사망 시각마다 record 누적 → 동시 진화 가능

### 2.8 가상 시간 + 빨리감기 (M7 추가)

모든 시스템이 `t`/`dt` 를 **명시적 인자**로 받는 구조 덕분에, BloodScene 한 곳에서 시간을 가속하면 전체가 자동으로 빨라짐.

**구현 (`scenes/BloodScene.ts`)**:
```typescript
private gameTime = 0;          // 가상 시간 (초). Phaser this.time.now 무시.
private speedMultiplier = 1;   // 1, 2, 4

override update(_time, delta) {
  if (this.paused) { ... return; }
  const dtReal = delta / 1000;
  const dt = dtReal * this.speedMultiplier;
  this.gameTime += dt;
  const t = this.gameTime;
  // ... 모든 시스템에 t/dt 전달
}
```

**키 매핑**:
- `[1]` 1배 (정상)
- `[2]` 2배
- `[3]` 4배
- `[P]` 일시정지 (gameTime 정지 → 시각/물리 모두 정지)

**HUD**: `speed: Nx` 표시 (FPS 옆).

**중요한 일관성 원칙**:
모든 시간 입력은 `this.gameTime` 기준이어야 함. Phaser `this.time.now` 와 섞이면 시각 불일치로 메커닉 깨짐.
- `pointerdown` 핸들러도 `this.gameTime` 사용 (충격파 발사 시각 일관성)
- ShockwaveSystem `initialTime: 0` (gameTime 시작점)
- 모든 시스템 update 가 t 인자를 우리 가상 시간으로 받음

**안정성**:
- 4배까지 안전 — `dt ≤ 0.067s`, 호중구 최대 이동 거리 `30 px/s × 0.067 = 2px` 로 충돌 거리보다 짧음
- 8배 이상은 충돌 누락 가능 → substep (한 프레임에 update 여러 번) 필요. 현재 보류.

**자동 가속되는 메커닉**:
모든 dt 의존 코드 (위치 적분, 마찰, 활성도 감쇠, 분열 진행, 영양분 부활, 커맨더 진화 카운트다운, 충격파 전파, contact 데미지 등) — 자동 작동.

**가속 영향 X**:
- FPS 측정 (실시간)
- 키 입력 / 충격파 발사 (실시간 이벤트, 다만 발사 시각은 gameTime 기준)
- HUD 갱신 (실시간)

### 2.9 B세포 + 항체 (M7 미사일 기지)

거의 정지된 백혈구가 발사하는 **지뢰형 발사체** 메커니즘. 호중구류의 직접 추격과 다른 비대칭 전술.

**B세포(BCELL) 명세**:
- 거의 정지 (speed 5), 낮은 HP (50), 직접 공격 X (attack 0)
- DNA `armament` 형질 활용 — 항체 발사 (`fireCooldown` 마다)
- 시야(`fireRange`) 안 가장 가까운 세균 / 없으면 무작위 방향
- 호중구류와 같은 풀 (WhiteCellBehaviorSystem) 에서 관리. DNA 동등성 (`cell.dna === BCELL`) 으로 분기.

**Antibody(항체) 명세**:
- 발사 직후 직선 이동 (`projectileSpeed`)
- 누적 이동 거리가 `projectileRange` 도달 시 → **정지** (vx=0, vy=0). 사라지지 않고 그 자리에 남음 (지뢰).
- 세균이 영양분처럼 추적 → 흡수 시 `isAbsorbed=true` + 세균 `applyDamage(damage)`
- 시각: 이동 중(`hsl 보라 l60`) / 정지(`hsl 보라 l45`) 두 색 분리

**armament 형질 (DNA)**:
```typescript
DNA.armament = {
  fireRange: number;        // 표적 인식 거리 (시야)
  fireCooldown: number;     // 발사 주기 (초)
  projectileSpeed: number;  // 발사체 속도 (px/s)
  projectileDamage: number; // 발사체 데미지
  projectileRange: number;  // 발사체 사거리 (px)
};
```

**BCELL 기본값**: fireRange 250, fireCooldown 3.0s, **speed 40 px/s**, damage 15, range 250 px.
다른 종은 모두 0 (발사 안 함).

**정지 항체 누적 방지** (M7 추가):
- `AntibodySystem` 생성자 인자 `maxStopped: number = 5`
- 정지 항체 수가 limit 초과 시 가장 오래된 (배열 인덱스 작은) 것부터 자동 정리 (FIFO)
- BloodScene 의 `ANTIBODY_MAX_STOPPED = 5` 상수로 노출 — 옵션으로 변경 가능

**세균-항체 상호작용 (BacteriaBehaviorSystem)**:
- 매 프레임 한 세균당 영양분 nearest + 항체 nearest 계산 → 가까운 쪽이 `senses.nearestNutrient`
- 행동(추적)은 동일 — 세균 입장에서 둘은 구분 안 됨 (영양분처럼 보임)
- 흡수 거리 도달 시 분기:
  - 영양분 → `nutrients.consume + registerAbsorb` (분열 카운터 ↑)
  - 항체 → `antibody.isAbsorbed=true + applyDamage(15)` (영양분 효과 X, HP 감소)
- 세균 hp 60 / 항체 데미지 15 → 4발 누적 흡수 시 사망

**시뮬레이션 효과**:
- B세포 1마리는 약하지만 시간 흐를수록 정지 항체가 **지뢰밭 누적** → 세균 통행 위험 ↑
- 호중구류 추격과 결합 시 세균 입장에서 다층 위협
- 정지 항체 영원히 누적 = 잠재적 부작용 (균형 조정 필요 시 페이드아웃 또는 대식세포 청소)

**구현 위치**:
- `entities/Antibody.ts` — 데이터 타입
- `systems/AntibodySystem.ts` — 풀 관리 (spawn, update, isAbsorbed 청소)
- `render/AntibodyRenderer.ts` — 보라 점 batch
- `entities/WhiteCell.ts` — `fireCooldownRemaining` 멤버 (B세포만 사용)
- `systems/WhiteCellBehaviorSystem.ts` — `processBCellFiring`, AntibodySystem 인자
- `systems/BacteriaBehaviorSystem.ts` — 영양분/항체 비교 + 흡수 분기, AntibodySystem 인자

### 2.10 T세포 + 호중구 진화 (M7)

백혈구 진영의 지휘관. 직접 공격은 안 하지만 **휘하 호중구를 강화**하는 매개체 — 세균 커맨더의 거울 종이지만 메커니즘은 다름.

**TCELL 명세**:

#### 두 카메라 + 두 Layer 아키텍처

페이즈 2 의 inner 엔티티들이 페이즈 1 의 world 좌표계를 공유하면 **zoom 비율로 인해 모든 크기/속도를 1/Z 로 정의해야 하는 문제** 발생 (예: zoom=6 시 visual 30px = world 5px). DNA 프리셋이 충돌하고 디자인이 어려워짐.

해결: **보조 카메라 cam2 (zoom=1, scroll=0,0)** 도입 → inner 엔티티는 자연 픽셀 좌표.

| 카메라 | 줌/스크롤 | 렌더 대상 | 동작 |
|---|---|---|---|
| `cam1` (main) | zoom 동적 / pan host | outer 만 (innerLayer ignore) | 페이즈 2 동안에도 zoomed 상태로 호중구 정지 화면 유지 |
| `cam2` | zoom=1 / scroll(0,0) | inner 만 (outerLayer ignore) | 페이즈 1 에선 visible=false, 페이즈 2 에서 visible=true |

GameObject 분리:
- `outerLayer` / `innerLayer` — `Phaser.GameObjects.Layer` 두 개
- **ADDED_TO_SCENE 리스너 (`routeAddedToOuter`)** — 새로 생성된 모든 GameObject 를 outerLayer 로 자동 라우팅 + `cam2.ignore(obj)` 적용 (기존 렌더러 코드 무수정)
- **`addToInner(obj)` 헬퍼** — inner 컨텐츠는 명시적으로 `innerLayer` 로 reparent + `cam1.ignore(obj)` + cam2 ignore 비트 해제 (라우팅이 set 한 cam2 ignore 취소)

⚠️ **`Camera.ignore(layer)` 는 호출 시점의 자식만 처리** — Phaser 내부적으로 layer 의 children 리스트를 한 번 walking 하며 cameraFilter 비트 set. 이후 추가되는 자식엔 적용 안 됨. 따라서 **객체 단위 ignore 가 필수**.

⚠️ **Phaser `Layer.addChildCallback` 가 `ADDED_TO_SCENE` 을 재발화** (`Layer.js` line 748) → 라우팅 리스너가 무한 루프 가능. 가드는 `gameObject.parentContainer` 가 아닌 **`gameObject.displayList`** 로 체크해야 함 (Phaser Layer 는 자식 추적을 displayList 속성으로 함).

#### 시계 분리

| 시계 | 진행 시점 | 리셋 |
|---|---|---|
| `gameTime` (= outerTime) | phase==='running' 만 | 안 함 |
| `innerTime` | phase==='inside' 만 | 매 진입 시 0 (단순화 — 누적 필요 시 한 줄 변경) |

`update()` 가 phase 분기:


### 2.12 페이즈 2 게임 룰 (Session 15 락인 → Session 17 갱신)

§2.11 의 진입/복귀 골격 위에 **실제 게임 룰** 정의. 아이디어 기획서 §"바이러스 변이 시나리오 (총 6종)" 의 변이 함수를 트리거하는 메커닉.

> **Session 17 갱신**: 쉴드 단일화 (3×3 매트릭스 폐기) + 변이 6종 메커니즘 상세 정의. 이전 안에서 미정 부분이 사용자 디자인으로 확정됨.

#### Wave 모델 (1 wave / 페이즈 2 진입)

| 항목 | 값 |
|---|---|
| Wave 당 바이러스 수 | **10발** 순차 spawn (시간차 ~0.8s) |
| 바이러스 패턴 분포 | 직진 4 / 지그재그 3 / 커브 3 (매 wave shuffle) |
| 바이러스 속도 | spawn 시 40~80 px/s 랜덤 — 도달 타이밍 분산 (한 번의 쉴드로 다발 차단 유도) |
| 쉴드 charges | **5회** (Session 17 — 이전 8회 안 폐기) |
| 쉴드 지속 | 0.3s |
| Wave 종결 | 10발 모두 처리 (쉴드 차단 or DNA 도달) → 변이 판정 → 페이즈 1 복귀 |

#### Hit → 변이율 모델

각 hit 마다 mutation rate +10%. 누적 0~100%.

| hit | 변이율 | 결과 변이 |
|---|---|---|
| 0 | 0% | 정상 (변이 없음) |
| 1~2 | 10~20% | 변이 1 좀비 |
| 3~4 | 30~40% | 변이 2 암세포 |
| 5~6 | 50~60% | 변이 3 형태 붕괴 |
| 7~8 | 70~80% | 변이 4 과민 |
| 9 | 90% | 변이 5 마비 |
| 10 | 100% | 변이 6 카오스 |

매핑은 결정형 (랜덤 X). hit 카운트만으로 변이 종류 결정.

#### DNA 시각화 — 10 세그먼트

DNA 나선을 시각상 10 구간으로 분할. 매 hit 마다 1 세그먼트가 corrupted (빨강 톤) 으로 변경 — 인덱스 0 부터 순차.

⚠️ 세그먼트는 **시각용 추상** 이지 실제 DNA 형질의 1:1 매핑 아님 (현 단계). hit 카운트만이 게임 로직에 영향. 추후 §3.3 매핑 정의 시 실제 DNA 형질에 연결할 수 있음.

#### 쉴드 (Session 17 단일화)

이전 안 (3×3 쉴드/바이러스 매트릭스, [1]/[2]/[3] 키 선택) **폐기**. 게임 디자인 재검토 결과 매트릭스 매칭은 학습 부담만 ↑ 즐거움 ↓ 로 판단. 단일 쉴드 + 바이러스 속도 랜덤화로 "타이밍" 만 핵심으로.

- 클릭 = 쉴드 발동 (charges 남고 비활성일 때만)
- 활성 0.3s 동안 DNA 중심 도달한 바이러스 = `hits` 미증가 + 즉시 소멸 + 차단 이펙트 (시안 원 펄스)
- 쉴드 시각: DNA 자체 strand/pair 라인 두께 ↑ (별도 영역 X — DNA 자체에 형성됨)
- 한 번의 발동으로 같은 타이밍의 다발 바이러스 다 차단 가능
- 바이러스 속도 랜덤 (40~80 px/s) → 빠른 놈/느린 놈 도달 타이밍 분산 → 유저가 "몰린 순간" 잡아야 함

#### 변이 적용 흐름

```
Wave 종결
  ↓
hits 카운트 → pickMutation(hits) → MutationKind | null
  ↓ (null 이면 변이 X)
host.dna = applyMutation(host.dna, kind)  // host 전용 클론에 적용
  ↓
CellRenderer handle 갱신 (재생성 또는 setDna)
  ↓
"변이 N 발생" 텍스트 1~2초 표시
  ↓
페이즈 1 복귀 — 변이된 호중구는 새 DNA 로 동작 (drives/color/speed 자동 반영)
```

⚠️ **호중구 DNA 인스턴스화 필수**: 현재 모든 NEUTROPHIL 이 같은 DNA 객체 reference 공유 (`dna === NEUTROPHIL`). 변이 = 그 reference 변형하면 모든 호중구 변이 버그. **호스트 cell 별 DNA 클론** 필요. 이는 Stage 2 의 큰 회귀 위험 작업 — `cell.dna === NEUTROPHIL` 같은 reference 비교를 `cell.dnaKind` 같은 라벨 비교로 전환.

**dna 변경의 시스템 의존**: dna 가 매 프레임 행동 시스템에 읽히므로 자동 반영. mutations.ts 함수는 dna 의 시각/기본 행동 형질만 변경하고, "행동 메커니즘 (정지/낙하/분열/scale/timer/폭발)" 은 시스템에서 `WhiteCell.mutation` 으로 분기.

#### 좀비 vs 카오스 — 호중구↔호중구 분기 공유

좀비 (호중구 우선 공격, 세균은 정상) 와 카오스 (호중구+세균 모두) 는 둘 다 호중구↔호중구 공격 분기가 필요. ContactSystem 에 한 번만 추가하고 mutation 으로 분기:
- mutation==='zombie' → 호중구↔호중구 페어, 호중구 vs 데미지 ×2
- mutation==='chaos' → 호중구↔호중구 + 호중구↔세균 모두, 데미지 ×3

#### 시스템 측 신규 작업 (Stage 11~15)

### 3.1 식별된 불일치

### 3.2 채택안: **객체가 정본, 나머지는 파생**

```typescript

  drives:   {
    avoidPredator:   { weight: number; triggerRadius: number };
    seekNutrient:    { weight: number };
    seekPrey:        { weight: number };
    seekCommander:   { weight: number };                        // M7 — NK 가 사용
    avoidWorker:     { weight: number; triggerRadius: number }; // M7 — NK 가 사용
    spaceAlly:       { weight: number; comfortRadius: number };
```

## 4. 변이 전파 모델

### 4.1 식별된 어색함

> "장면 2의 결과는 장면 1의 모든 B세포에 동일 적용"

- 한 세포 감염이 즉시 전체로 점프 → 직관 위배
- 부분성공(`protectionRate`) 표현 어려움

### 4.2 채택안: **점진적 분열 전파**

```
감염 B세포 1개
  ↓ (DNA.meta.divide > 0 이므로 분열)
변이 B세포 2개 → 4개 → 8개 ...
  ↓ (시간 경과)
화면의 B세포 비율이 점진적으로 변이로 치환됨
```

- 부분성공: `protectionRate`에 비례하여 `meta.divide` 값을 낮춤 → 전파 속도 ↓
- 시각적 드라마: 점점 색이 바뀌는 군집

새 종족(예: T세포, NK세포) 을 추가하려면:
1. `domain/dna.ts` 에 새 프리셋 (DNA 객체)
2. `entities/` 에 새 클래스 — `LivingCell` extends, `updateAlive` 구현
3. (필요 시) 종족별 BehaviorSystem 또는 기존 시스템 확장
4. `BloodScene` 에서 인스턴스 생성 + 적절한 시스템에 등록

이전엔 `WhiteCell` 와 `Bacteria` 의 100+ 줄 boilerplate 를 복사해야 했지만, 이제는 종족 고유 로직만 작성하면 됨.

**원칙**:
- `domain/`: 순수 로직, Phaser 의존 없음, 단위 테스트 가능
- `entities/`: 게임 오브젝트, Phaser 의존 OK
- `render/`: 렌더링 어댑터, 교체 가능
- `systems/`: 여러 엔티티에 걸친 로직

언어는 **TypeScript** 권장 (DNA 스키마 일관성 강제, 리팩토링 안전성).
