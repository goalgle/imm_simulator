## 문서의 목적

아이디어 기획서가 **"무엇을 만들 것인가(What)"** 를 정의한다면,
이 문서는 **"어떻게 만들 것인가(How)"** 를 정의한다.

| 구분 | 아이디어 기획서 | 시스템 구현 기획서 (본 문서) |
|---|---|---|
| 관심사 | 게임 컨셉, 메커닉, 콘텐츠 | 렌더링, 데이터 모델, 아키텍처 |

| 독자 | 디자이너 / 본인 | 구현자 / 본인 |

아이디어 기획서의 항목 중 **구현 가능성/성능/일관성에 영향을 주는 부분**만 본 문서에서 다룬다.

## 1. 핵심 기술 결정

### 1.1 게임 엔진: Phaser 3

확정. 아이디어 기획서 결정 사항 유지.

### 1.2 렌더링 전략

**원칙**: 메인 오브젝트(세포/세균/바이러스)는 **함수 평가 결과**여야 한다. 비트맵 스프라이트나 미리 그려둔 polygon 데이터로 표현하지 않는다.

#### 후보 비교

| 방식 | 어떻게 | 100개 기준 성능 | 함수 적합성 | 학습 부담 |
|---|---|---|---|---|
| A. `Graphics` + path redraw | 매 프레임 `lineTo` 60점 | ❌ 약 50개 한계 | ⭕ polygon 근사 | 낮음 |
| B. `Mesh` + 동적 vertex | CPU 계산 후 vertex buffer 갱신 | ⭕ 200~300개 | ⭕ polygon 근사 | 중간 |
| C. Custom Vertex Shader | GPU에서 `r(θ,t)` 계산 | ⭐ 1000개+ | ⭕ GPU 평가 | 높음 |
| D. Fragment Shader (SDF) | 픽셀 단위 implicit field 평가 | ⭐ 수백 개 | ⭐⭐ 함수 = 형태 | 중간 |

#### 채택안: **per-cell Graphics + 동적 polygon redraw** (B 방식의 단순 변형)

```
Phase 1 (MVP):  Phaser.GameObjects.Graphics × N  (per-cell, fillPoints 매 프레임)
                ↓ 게임플레이 검증
Phase 2 (필요시): D 방식 (Fragment Shader / SDF) 로 교체 — 어댑터 교체로 처리
```

**근거 (M0 검증 결과)**:

> 측정 환경: Apple Silicon Mac 추정, Phaser 3.80.1 WebGL 렌더러, 단일 기기 측정.
> 보강 필요: Chrome CPU throttling을 사용할 수 있는 환경에서 약한 기기 시뮬레이션 재측정.

| 시나리오 | FPS 결과 | 비고 |
|---|---|---|
| 5000개 / 64 verts / homo / per-cell | 60 (GO) | baseline |
| 5000개 / 96 verts / homo / per-cell | 30~60 (CONDITIONAL) | vertex 정밀도 한계점 |
| 5000개 / 64 verts / mixed(7종) / per-cell | ≈ homo와 동일 | 색 다양성 영향 미미 |
| color-grouped 정렬 | random/y-sorted 대비 미세 우위 | 효과 작음 |

**해석**: 워크로드는 **CPU-bound** (sin × 3 × verts × cells ≈ 매 프레임 수십만 호출). GPU/색 batch 비용은 무시 가능 수준.

**결론**:
- **MVP 100~500개 목표는 광범위한 안전 마진**으로 통과 (Apple Silicon 기준 50배 이상 여유).
- 색별 정렬 같은 batch 최적화는 **불필요** — 코드 단순성 우선.
- 진짜 최적화 포인트는 CPU 측 → **`sin()` 룩업 테이블, vertex 객체 재사용** 이 효과 클 가능성. M1에서 함께 구현.
- D 방식(SDF)은 **현 시점 도입하지 않음**. 본 게임 진행 중 한계 도달 시에만 어댑터 교체로 처리.
- B(Mesh) 방식보다 **Graphics + fillPoints가 더 단순**하고 결과 동일 → Mesh API 학습 부담 제거.

#### 렌더 어댑터 인터페이스 (양 방식 공통)

```typescript
interface CellRenderer {
  create(dna: DNA, position: Vec2): RenderHandle;
  update(handle: RenderHandle, dna: DNA, tempState: TempState, t: number): void;
  destroy(handle: RenderHandle): void;
}

// MeshCellRenderer: B 방식 구현체
// SDFCellRenderer:  D 방식 구현체 (Phase 2)
```

본 게임 로직(`WhiteCell`, `Bacteria` 등)은 **인터페이스만 의존**한다. 렌더러 교체 시 게임 로직 변경 없음.

### 1.3 충돌 모델

- **시각**: 함수 기반 변형 형태 (Mesh/SDF)
- **물리**: `baseRadius` 기반 **고정 원형 hitbox** (Phaser Arcade Physics 그대로 사용)
- **근거**: 변형되는 외곽선 충돌은 비용이 크고, 게임플레이상 정확도 요구 낮음. 시각 ≠ 물리 분리는 표준 관행.

### 1.4 좌표/시간 단위

- 좌표: Phaser 기본 (px, 좌상단 0,0)
- 시간: 초 단위 float (`t`, `dt`)
- 룩업 테이블 해상도: **0.0167s (60Hz)** — 아이디어 기획서의 0.1s(10Hz)는 시각적 떨림 우려로 상향 조정

## 2. 게임 컨셉 통일 (개입 강도)

### 2.1 식별된 모순

아이디어 기획서:
- 프로젝트 개요: "최소 유저 인터렉션 시뮬레이션"
- 장면 2: A/D 키 수동 발사 타워 디펜스 (적극적 입력)

→ 두 장면의 톤이 다른 게임처럼 느껴질 위험.

### 2.2 채택 방향: **"관전형 + 결정적 개입"**

| 장면 | 인터렉션 강도 | 플레이어 행위 |
|---|---|---|
| 장면 1 (혈관 속) | 낮음 (관전 + 가벼운 개입) | 줌, 일시정지, **충격파 발사**(클릭/탭으로 세포를 밀어 이동 유도) |
| 장면 2 (세포 속) | 중간 (선택형) | 포탑 배치/타입 선택, 자원 분배 — 실시간 정밀 조작 X |

**핵심 차이**: 장면 2를 "수동 슈팅" → "**전술적 선택 + 자동 전투 관전**" 으로 톤 다운.

#### 2.2.1 장면 1 — 충격파 인터렉션 (M1.5 구현 완료)

플레이어가 화면을 클릭/탭하면 그 지점에서 파동이 퍼지며 영향권 안의 세포를 발사점 반대 방향으로 민다. 자원(charges)이 있어 무제한 사용 불가 — 시뮬레이션 톤 유지.

| 항목 | 기본값 | 위치 | 의미 |
|---|---|---|---|
| 동시 보유 | 5발 | `BloodScene.SHOCKWAVE_CONFIG.maxCharges` | 게이지처럼 작동 |
| 충전 속도 | 3초당 1발 | `rechargeIntervalSec` | 시간 따라 자동 회복 |
| 파동 전파 속도 | 280 px/s | `waveTemplate.speed` | 빠를수록 즉발적 |
| 파동 수명 | 1.2 s | `waveTemplate.duration` | 길수록 멀리 영향 |
| 파동 세기 | 600 px/s² | `waveTemplate.power` | 임펄스 가속도 |
| 링 두께 | 50 px | `waveTemplate.bandwidth` | 영향권의 굵기 |
| 세포 마찰 | 1.5 /sec | `WhiteCell.FRICTION` | 멈출 때까지 시간 |
| 벽 반사율 | 0.5 | `WhiteCell.WALL_BOUNCE` | 0=흡수, 1=완전 탄성 |

**도메인 분리**: `domain/shockwave.ts` 는 Phaser 의존 0인 순수 함수 (`shockwaveRadius`, `shockwaveImpulse`, `isShockwaveAlive`). 단위 테스트로 동작 검증.

**향후 확장 여지**:
- 충격파 종류 다양화 (당기는 파동, 약화 효과 등) — 새 `waveTemplate` 추가만으로 가능
- 게임 내 의미 부여: "혈류 펌핑" / "의료 개입" 등 컨셉적 정당화는 추후 결정
- 장면 2와 일관성 위해 동일 자원 모델 차용 가능

### 2.3 오브젝트 분류

게임 내 모든 표시 가능한 오브젝트의 상위 분류. DNA 보유 여부 / 충격파 영향 여부 / 충돌 처리 방식이 분류별로 다름.

| 분류 | 예 | 생명체 | DNA | 충격파 영향 | 백혈구 충돌 |
|---|---|---|---|---|---|
| **백혈구** | 호중구, T세포, NK ... | ✅ | ✅ | ✅ 받음 | — |
| **세균** | 일반 세균 | ✅ | ✅ | ✅ 받음 | ✅ 접촉 반응 |
| **바이러스** | (M5+) | ⚠️ 준생명 | 일부 | TBD | ❌ DNA 침투 |
| **영양분(Nutrient)** | 생체 영양소 | ❌ | ❌ | ❌ **정지 고정** | ❌ **통과** |
| **고름(Pus)** | 백혈구 잔해 | ❌ | ❌ | TBD | ❌ |

**영양분(Nutrient) 명세**:
- 화면 내 절대값 고정 슬롯 (시작값 **40**)
- 무작위 위치, 정지 (이동 없음)
- 세균이 흡수 시 즉시 비활성화 + **4초 후** 다른 무작위 위치에 부활 (총수 보존, 자원 압박)
- 백혈구는 충돌 없이 통과 — 단, **통과 시 약간의 시각 효과 예정** (구체 디자인 TODO)
- 충격파 시스템에 의해 움직이지 않음 (`ShockwaveSystem.applyToCells` 적용 대상에서 제외)
- 시각: 단순한 작은 점/원 (함수 기반 형태 X — 생명체 아니므로 다른 코드 경로)

**시체(Corpse) 명세** (M3.4 도입):
- 백혈구/세균이 hp=0 도달 시 같은 인스턴스가 시체 모드로 전환 (별도 클래스 없음 — `isDead()` 분기)
- 시각: **채도 0 (회색) + 형태 떨림 정지 + 최소 크기(MIN_SCALE=0.5) 유지**
- 행동/충돌/임펄스 모두 정지: drives senses 후보 X, ShockwaveSystem 임펄스 X, ContactSystem 데미지 X
- **분리력 제외 → 겹침 허용**
- **중력만 작용**: vy += GRAVITY × dt, 화면 바닥(큰 Y) 도달 시 vy=0 침전
- 시체 페이드아웃/대식세포 흡수는 M4 에서 (현재는 영원히 누적 — 검수 후 결정)

### 2.4 세균 행동 모델

세균의 행동 동기 = **생존(영양분 흡수) + 자가증식(분열)**.

#### 2.4.1 1단계 — 단순 추적 (M2.1)

```
1. 가장 가까운 영양분 탐색
2. 그 영양분으로 이동 (속도 = DNA.behavior.speed)
3. 도달 시 흡수 → 흡수 카운터 +1, 영양분 풀에서 1개 소비/재생성
4. 흡수 카운터가 분열 임계치 N=3 도달 시 분열 시작
5. 0.5초간 시각적으로 부풀음 → 자기 복제 1마리, 카운터 0
```

이 단계에선 동족/포식자 인식 없음. 세균은 영양분만 본다.

#### 2.4.2 2단계 — drives 모델 + 관성 (M2.2 ✅ 완료)

**결정 모델**: 부드러운 우선순위 (가중 벡터 합 + 거리 기반 활성도).

**DNA 스키마 확장 (실제 구현)**:
```typescript
DNA.behavior.turnRate: number;  // 1/sec — 클수록 빠른 방향 전환 (관성 ↔ 즉시)
DNA.drives = {
  avoidPredator: { weight, triggerRadius };  // 1순위 (큰 weight)
  seekNutrient:  { weight };                  // 2순위
  spaceAlly:     { weight, comfortRadius };   // 3순위 (동족 회피)
  seekAlly:      { weight };                  // 군집형 종 용도 (다른 종에서 활성)
};
```

배열이 아닌 **객체**로 둔 이유: 모든 필드가 숫자 → 바이러스 변이가 산술 연산 (`weight *= 1.3`) 으로 일관 처리. 새 종 = 같은 구조에서 값만 다름.

**행동 합성**:
1. 각 drive 평가 → (단위 방향 벡터, 활성도 0~1)
2. 가중 합: `Σ dir × activation × weight`
3. 정규화 → 단위 방향
4. desired velocity = 단위 방향 × `behavior.speed`
5. 부드러운 가속: `v += (desired_v - v) × (1 - exp(-turnRate × dt))`

**활성도 규칙**:
- `avoidPredator`: 가장 가까운 포식자가 `triggerRadius` 안에 있을 때만, 가까울수록 ↑
- `seekNutrient`: 영양분이 있으면 항상 1
- `spaceAlly`: 가장 가까운 동족이 `comfortRadius` 안에 있을 때만, 가까울수록 ↑
- `seekAlly`: 동족이 있으면 항상 1

**호중구 영향**: 모든 drive weight=0, turnRate=0 (자체 추진하지 않으므로 무영향). 충격파로만 이동.

#### 분리력 (M2.2 ✅ 완료)

DNA 형질이 아닌 **물리적 처리**. 같은 종족 쌍별 검사, 거리 < (r1+r2+padding) 이면 멀어지는 가속도 누적.

- 위치: `src/domain/separation.ts` (순수 함수)
- 매 프레임 BloodScene 에서 두 번 호출 (백혈구끼리, 세균끼리)
- 다른 종족 간 분리는 M3 충돌 시스템에서 별도 처리
- 파라미터: `padding=4, strength=400 px/s²` (조정 가능)

### 2.5 시각 채널 분리 (M3.4 도입)

엔티티의 일시 자극을 **3채널** 로 구분하여 렌더러가 합성. 각 채널이 다른 시각 특징을 가져 사용자가 자극의 종류를 구분 가능.

```typescript
type VisualState = {
  shock: number;   // 0~1, 충격파 임펄스
  combat: number;  // 0~1, 적과 접촉
  life: number;    // 0~1, 1=살아있음, 0=완전 사망
};
```

| 채널 | 트리거 | 시각 효과 |
|---|---|---|
| **shock** | 충격파 임펄스 (사용자 클릭/탭) | 채도 ↑ + 명도 ↓ + 떨림 진폭 ↑ — "자기 색이 진해짐" |
| **combat** | 호중구 ↔ 세균 접촉 | hue 를 빨강(0°)으로 lerp + 채도 ↑ + 떨림 ↑ — "다른 색이 됨" |
| **life** | hp=0 도달 (사망) | 채도 ×0 (회색) + ampBoost ×0 (떨림 정지) |

세 채널이 동시 작용 가능 (충격파 맞으면서 세균과 접촉 중인 호중구는 "약간 빨개진 진한 분홍이 떨림"). 합성 공식은 `GraphicsCellRenderer` 내부:

```
hue   = baseH + (RED - baseH) × combat × 0.6
sat   = (baseS + 15·shock + 20·combat) × life
light = baseL - 25·shock
amp   = (1 + 0.5·shock + 0.4·combat) × life
```

**확장 여지**: `tempState` (M5+) 같은 다른 자극도 새 채널로 추가 가능. 인터페이스만 늘리면 됨.

### 2.6 호중구 재생산 (M5.4 — 대식세포 + 슈퍼 호중구)

면역 체계의 자가 균형 메커니즘. 사망한 호중구가 단순 손실이 아닌 새 호중구의 자원이 됨.

**대식세포(MACROPHAGE) 명세**:
- 화면 바닥(`Y = bounds.height - r`)에 고정, **X 좌우만** 이동
- 시체(`isSettled()` = 죽었고 `vy=0, vx=0`) 만 인터렉션 — 살아있는 세포/세균 무시
- **충격파 영향 X** — 정해진 동선
- 가장 가까운 침전 시체 X 좌표로 추격 → 흡수 거리 도달 시 `isAbsorbed=true` + 점수 누적
- 시각: base 40 (가장 큼), 초록 `hsl(120, 30, 50)`, drives 모두 0

**점수 시스템**:
- 세균 시체 흡수: **+10**
- 호중구 시체 흡수: **+20**
- 호중구 점수는 `whiteCellScoreInPool` 로 별도 추적 (슈퍼 조건용)

**백혈구 생산 분기** (M7 갱신):
- `totalScore ≥ 100` 도달 시 백혈구 1마리 생산 + 카운터 -100 (호중구 풀은 0 리셋)
- 생산 위치: **대식세포 정확한 위치에서 위로 솟구치는 효과** (vy=-180, 좌우 ±40 무작위)
- 생산 종류 분기 (우선순위):
  1. **1/10 확률 → NK 세포** (커맨더 우선 추적 암살자)
  2. **호중구 점수 ≥ 40 → 슈퍼 호중구** (호중구 사체가 절반 이상)
  3. **그 외 → 일반 호중구**

**백혈구 비교**:

| 항목 | NEUTROPHIL | NEUTROPHIL_SUPER | NK_CELL |
|---|---|---|---|
| base | 32 | 40 | **22** (작은 체구) |
| color | 연한 분홍 `h322 s53 l81` | 진한 보라 `h280 s65 l55` | 진한 청보라 `h260 s55 l45` |
| maxHp | 100 | 180 | 80 |
| attack | 20 | 30 | **35** (가장 강력) |
| speed | 15 | 32 | 30 |
| turnRate | 1.5 | 2.0 | 3.0 (가장 민첩) |
| **minSpeedRatio** | 0 | 0 | **1.0** (HP 무관) |
| 추적 우선 | 가장 가까운 세균 | 가장 가까운 세균 | **커맨더 우선**, 일반은 fallback |
| 일반 세균 회피 | X | X | **80px 안에서 우회** |
| recovery | 0.6 | 0.7 | 0.8 |

**시뮬레이션 균형 효과**:
- 세균이 약하면 → 호중구 시체 적음 → 평범 호중구만 생산 → 세균 우세 유지
- 세균이 강해 호중구 많이 잡으면 → 호중구 점수 높음 → 슈퍼 호중구 생산 → 면역 반격
- 가끔 1/10 확률로 NK 등장 → 커맨더만 노림 → 팀 와해 + 진화 대기
- 자가 균형 — 외부 개입 없이 게임이 스스로 조정됨

**호중구 처치 보상 (M5.3 보강)**:
세균이 호중구를 죽인 순간 데미지 가한 세균의 팀 전체에 `registerAbsorb` 호출 → 영양분 1개 흡수와 동등 효과 (멤버 분열 가까워짐, 커맨더 시야/지휘범위 ↑).

#### 2.6.1 호중구 자기 융합 (M7 추가)

슈퍼 호중구 생산의 **두 번째 경로** — 외부 자원(대식세포 점수) 외에 내부 협력으로도 진화. 약한 동료를 살리지 못해도 "흡수해서 더 강한 호중구로 환원" 하는 면역 자가 회복 메커니즘.

**행동 분기 (NEUTROPHIL 한정)**:
- 자기 약함 (`hpRatio < WEAK_HP_THRESHOLD = 0.25`): 가장 가까운 강한 동료 추적 (세균보다 우선) — 흡수 받기 위해
- 자기 강함 + 약한 동료 있음: 약한 동료 추적 (세균보다 우선) — 흡수 시도
- 그 외: 기존 (세균 추적)

이 분기는 drives 변경 없이 `WhiteCellBehaviorSystem` 의 `senses.nearestPrey` 동적 결정으로 구현 (`findAllyTarget`).

**흡수 조건**:
- 둘 다 살아있는 NEUTROPHIL (NK_CELL / NEUTROPHIL_SUPER 는 DNA 동등성 비교로 제외)
- 거리 < `r1 + r2 + FUSION_PADDING(2)`
- 한 쪽만 약함 (둘 다 약하거나 둘 다 강하면 흡수 X)

**처리**:
- 약한 호중구 → `isAbsorbed=true` (시체 X, 즉시 소멸)
- 강한 호중구 → `mergeCounter += 1`
- `mergeCounter ≥ 2` → 자기 isAbsorbed=true + 같은 자리에 NEUTROPHIL_SUPER spawn

**파라미터**:
- `WEAK_HP_THRESHOLD = 0.25` (export const, `entities/WhiteCell.ts`)
- `FUSION_PADDING = 2` px (`systems/WhiteCellBehaviorSystem.ts`)
- `FUSION_THRESHOLD = 2` (흡수 횟수)

**구현 위치**:
- `entities/WhiteCell.ts` — `mergeCounter`, `isWeak()` 헬퍼, `WEAK_HP_THRESHOLD` 상수
- `systems/WhiteCellBehaviorSystem.ts` — `findAllyTarget()`, `processFusion()`, 매 프레임 update 끝에 호출

**시뮬레이션 균형 효과**:
- 세균이 약한 호중구를 자주 만들수록 → 융합 활성 → 슈퍼 호중구 자가 생성 → 면역 반격 강화
- 대식세포 경로(외부 자원)와 융합 경로(내부 협력) 가 동시 작동 — 두 가지 회복 채널

### 2.7 커맨더 진화 (M7)

커맨더가 사망해도 세균 생태계가 영구 정지되지 않도록 **자동 진화** 메커니즘.

```
커맨더 사망
  ↓ TeamSystem.commanderDeathTimes 에 시각 기록 + 팀 즉시 해체
  ↓ 10초 경과
  ↓ TeamSystem.consumeExpiredDeathRecords 가 만료 record 반환
  ↓ BloodScene.evolveCommanders 가 살아있는 일반 세균 1마리 무작위 선택
  ↓ 그 자리에서 즉시 BACTERIA_COMMANDER 로 변환 (기존 세균 isAbsorbed=true 로 정리)
  ↓ 새 커맨더가 다시 멤버 영입 시작
```

**조건/예외**:
- 진화 대기 중에 일반 세균이 모두 사라지면 진화 무산 (record 는 이미 소비됨, 다음 사망 시 재시도 없음)
- 다중 커맨더 (현재 게임에 1마리뿐이지만) 라면 사망 시각마다 record 누적 → 동시 진화 가능

### 2.8 가상 시간 + 빨리감기 (M7 추가)

모든 시스템이 `t`/`dt` 를 **명시적 인자**로 받는 구조 덕분에, BloodScene 한 곳에서 시간을 가속하면 전체가 자동으로 빨라짐.

**구현 (`scenes/BloodScene.ts`)**:
```typescript
private gameTime = 0;          // 가상 시간 (초). Phaser this.time.now 무시.
private speedMultiplier = 1;   // 1, 2, 4

override update(_time, delta) {
  if (this.paused) { ... return; }
  const dtReal = delta / 1000;
  const dt = dtReal * this.speedMultiplier;
  this.gameTime += dt;
  const t = this.gameTime;
  // ... 모든 시스템에 t/dt 전달
}
```

**키 매핑**:
- `[1]` 1배 (정상)
- `[2]` 2배
- `[3]` 4배
- `[P]` 일시정지 (gameTime 정지 → 시각/물리 모두 정지)

**HUD**: `speed: Nx` 표시 (FPS 옆).

**중요한 일관성 원칙**:
모든 시간 입력은 `this.gameTime` 기준이어야 함. Phaser `this.time.now` 와 섞이면 시각 불일치로 메커닉 깨짐.
- `pointerdown` 핸들러도 `this.gameTime` 사용 (충격파 발사 시각 일관성)
- ShockwaveSystem `initialTime: 0` (gameTime 시작점)
- 모든 시스템 update 가 t 인자를 우리 가상 시간으로 받음

**안정성**:
- 4배까지 안전 — `dt ≤ 0.067s`, 호중구 최대 이동 거리 `30 px/s × 0.067 = 2px` 로 충돌 거리보다 짧음
- 8배 이상은 충돌 누락 가능 → substep (한 프레임에 update 여러 번) 필요. 현재 보류.

**자동 가속되는 메커닉**:
모든 dt 의존 코드 (위치 적분, 마찰, 활성도 감쇠, 분열 진행, 영양분 부활, 커맨더 진화 카운트다운, 충격파 전파, contact 데미지 등) — 자동 작동.

**가속 영향 X**:
- FPS 측정 (실시간)
- 키 입력 / 충격파 발사 (실시간 이벤트, 다만 발사 시각은 gameTime 기준)
- HUD 갱신 (실시간)

**구현 위치**:
- `src/entities/Macrophage.ts` — 바닥 고정 + X 이동 + 충격파/충돌 무관
- `src/systems/MacrophageSystem.ts` — 시체 추적 + 흡수 + 점수 + `consumeScoreForProduction()`
- `src/scenes/BloodScene.ts` — 매 프레임 `tryProduceWhiteCell` 호출, `isAbsorbed=true` 인 시체 청소

## 4. 변이 전파 모델

### 4.1 식별된 어색함

> "장면 2의 결과는 장면 1의 모든 B세포에 동일 적용"

- 한 세포 감염이 즉시 전체로 점프 → 직관 위배
- 부분성공(`protectionRate`) 표현 어려움

### 4.2 채택안: **점진적 분열 전파**

```
감염 B세포 1개
  ↓ (DNA.meta.divide > 0 이므로 분열)
변이 B세포 2개 → 4개 → 8개 ...
  ↓ (시간 경과)
화면의 B세포 비율이 점진적으로 변이로 치환됨
```

- 부분성공: `protectionRate`에 비례하여 `meta.divide` 값을 낮춤 → 전파 속도 ↓
- 시각적 드라마: 점점 색이 바뀌는 군집
