## 1. 핵심 기술 결정

### 1.1 게임 엔진: Phaser 3

확정. 아이디어 기획서 결정 사항 유지.

### 1.2 렌더링 전략

**원칙**: 메인 오브젝트(세포/세균/바이러스)는 **함수 평가 결과**여야 한다. 비트맵 스프라이트나 미리 그려둔 polygon 데이터로 표현하지 않는다.

#### 후보 비교

| 방식 | 어떻게 | 100개 기준 성능 | 함수 적합성 | 학습 부담 |
|---|---|---|---|---|
| A. `Graphics` + path redraw | 매 프레임 `lineTo` 60점 | ❌ 약 50개 한계 | ⭕ polygon 근사 | 낮음 |
| B. `Mesh` + 동적 vertex | CPU 계산 후 vertex buffer 갱신 | ⭕ 200~300개 | ⭕ polygon 근사 | 중간 |
| C. Custom Vertex Shader | GPU에서 `r(θ,t)` 계산 | ⭐ 1000개+ | ⭕ GPU 평가 | 높음 |
| D. Fragment Shader (SDF) | 픽셀 단위 implicit field 평가 | ⭐ 수백 개 | ⭐⭐ 함수 = 형태 | 중간 |

#### 채택안: **per-cell Graphics + 동적 polygon redraw** (B 방식의 단순 변형)

```
Phase 1 (MVP):  Phaser.GameObjects.Graphics × N  (per-cell, fillPoints 매 프레임)
                ↓ 게임플레이 검증
Phase 2 (필요시): D 방식 (Fragment Shader / SDF) 로 교체 — 어댑터 교체로 처리
```

**근거 (M0 검증 결과)**:

> 측정 환경: Apple Silicon Mac 추정, Phaser 3.80.1 WebGL 렌더러, 단일 기기 측정.
> 보강 필요: Chrome CPU throttling을 사용할 수 있는 환경에서 약한 기기 시뮬레이션 재측정.

| 시나리오 | FPS 결과 | 비고 |
|---|---|---|
| 5000개 / 64 verts / homo / per-cell | 60 (GO) | baseline |
| 5000개 / 96 verts / homo / per-cell | 30~60 (CONDITIONAL) | vertex 정밀도 한계점 |
| 5000개 / 64 verts / mixed(7종) / per-cell | ≈ homo와 동일 | 색 다양성 영향 미미 |
| color-grouped 정렬 | random/y-sorted 대비 미세 우위 | 효과 작음 |

**해석**: 워크로드는 **CPU-bound** (sin × 3 × verts × cells ≈ 매 프레임 수십만 호출). GPU/색 batch 비용은 무시 가능 수준.

**결론**:
- **MVP 100~500개 목표는 광범위한 안전 마진**으로 통과 (Apple Silicon 기준 50배 이상 여유).
- 색별 정렬 같은 batch 최적화는 **불필요** — 코드 단순성 우선.
- 진짜 최적화 포인트는 CPU 측 → **`sin()` 룩업 테이블, vertex 객체 재사용** 이 효과 클 가능성. M1에서 함께 구현.
- D 방식(SDF)은 **현 시점 도입하지 않음**. 본 게임 진행 중 한계 도달 시에만 어댑터 교체로 처리.
- B(Mesh) 방식보다 **Graphics + fillPoints가 더 단순**하고 결과 동일 → Mesh API 학습 부담 제거.

#### 렌더 어댑터 인터페이스 (양 방식 공통)

```typescript
interface CellRenderer {
  create(dna: DNA, position: Vec2): RenderHandle;
  update(handle: RenderHandle, dna: DNA, tempState: TempState, t: number): void;
  destroy(handle: RenderHandle): void;
}

// MeshCellRenderer: B 방식 구현체
// SDFCellRenderer:  D 방식 구현체 (Phase 2)
```

본 게임 로직(`WhiteCell`, `Bacteria` 등)은 **인터페이스만 의존**한다. 렌더러 교체 시 게임 로직 변경 없음.

### 1.3 충돌 모델

- **시각**: 함수 기반 변형 형태 (Mesh/SDF)
- **물리**: `baseRadius` 기반 **고정 원형 hitbox** (Phaser Arcade Physics 그대로 사용)
- **근거**: 변형되는 외곽선 충돌은 비용이 크고, 게임플레이상 정확도 요구 낮음. 시각 ≠ 물리 분리는 표준 관행.

### 1.4 좌표/시간 단위

- 좌표: Phaser 기본 (px, 좌상단 0,0)
- 시간: 초 단위 float (`t`, `dt`)
- 룩업 테이블 해상도: **0.0167s (60Hz)** — 아이디어 기획서의 0.1s(10Hz)는 시각적 떨림 우려로 상향 조정

## 2. 게임 컨셉 통일 (개입 강도)

### 2.1 식별된 모순

아이디어 기획서:
- 프로젝트 개요: "최소 유저 인터렉션 시뮬레이션"
- 장면 2: A/D 키 수동 발사 타워 디펜스 (적극적 입력)

→ 두 장면의 톤이 다른 게임처럼 느껴질 위험.

### 2.2 채택 방향: **"관전형 + 결정적 개입"**

| 장면 | 인터렉션 강도 | 플레이어 행위 |
|---|---|---|
| 장면 1 (혈관 속) | 낮음 (관전 + 가벼운 개입) | 줌, 일시정지, **충격파 발사**(클릭/탭으로 세포를 밀어 이동 유도) |
| 장면 2 (세포 속) | 중간 (선택형) | 포탑 배치/타입 선택, 자원 분배 — 실시간 정밀 조작 X |

**핵심 차이**: 장면 2를 "수동 슈팅" → "**전술적 선택 + 자동 전투 관전**" 으로 톤 다운.

#### 2.2.1 장면 1 — 충격파 인터렉션 (M1.5 구현 완료)

플레이어가 화면을 클릭/탭하면 그 지점에서 파동이 퍼지며 영향권 안의 세포를 발사점 반대 방향으로 민다. 자원(charges)이 있어 무제한 사용 불가 — 시뮬레이션 톤 유지.

| 항목 | 기본값 | 위치 | 의미 |
|---|---|---|---|
| 동시 보유 | 5발 | `BloodScene.SHOCKWAVE_CONFIG.maxCharges` | 게이지처럼 작동 |
| 충전 속도 | 3초당 1발 | `rechargeIntervalSec` | 시간 따라 자동 회복 |
| 파동 전파 속도 | 280 px/s | `waveTemplate.speed` | 빠를수록 즉발적 |
| 파동 수명 | 1.2 s | `waveTemplate.duration` | 길수록 멀리 영향 |
| 파동 세기 | 600 px/s² | `waveTemplate.power` | 임펄스 가속도 |
| 링 두께 | 50 px | `waveTemplate.bandwidth` | 영향권의 굵기 |

**향후 확장 여지**:
- 충격파 종류 다양화 (당기는 파동, 약화 효과 등) — 새 `waveTemplate` 추가만으로 가능
- 게임 내 의미 부여: "혈류 펌핑" / "의료 개입" 등 컨셉적 정당화는 추후 결정
- 장면 2와 일관성 위해 동일 자원 모델 차용 가능

### 2.3 오브젝트 분류

게임 내 모든 표시 가능한 오브젝트의 상위 분류. DNA 보유 여부 / 충격파 영향 여부 / 충돌 처리 방식이 분류별로 다름.

| 분류 | 예 | 생명체 | DNA | 충격파 영향 | 백혈구 충돌 |
|---|---|---|---|---|---|
| **백혈구** | 호중구, T세포, NK ... | ✅ | ✅ | ✅ 받음 | — |
| **세균** | 일반 세균 | ✅ | ✅ | ✅ 받음 | ✅ 접촉 반응 |
| **바이러스** | (M5+) | ⚠️ 준생명 | 일부 | TBD | ❌ DNA 침투 |
| **영양분(Nutrient)** | 생체 영양소 | ❌ | ❌ | ❌ **정지 고정** | ❌ **통과** |
| **고름(Pus)** | 백혈구 잔해 | ❌ | ❌ | TBD | ❌ |

**영양분(Nutrient) 명세**:
- 화면 내 절대값 고정 개수 (시작값 **40**)
- 무작위 위치, 정지 (이동 없음)
- 세균이 흡수 시 즉시 소멸 + 다른 무작위 위치에 1개 재생성 (총수 보존)
- 백혈구는 충돌 없이 통과 — 단, **통과 시 약간의 시각 효과 예정** (구체 디자인 TODO)
- 충격파 시스템에 의해 움직이지 않음 (`ShockwaveSystem.applyToCells` 적용 대상에서 제외)
- 시각: 단순한 작은 점/원 (함수 기반 형태 X — 생명체 아니므로 다른 코드 경로)

### 2.4 세균 행동 모델

세균의 행동 동기 = **생존(영양분 흡수) + 자가증식(분열)**.

#### 2.4.1 1단계 — 단순 추적 (M2.1)

```
1. 가장 가까운 영양분 탐색
2. 그 영양분으로 이동 (속도 = DNA.behavior.speed)
3. 도달 시 흡수 → 흡수 카운터 +1, 영양분 풀에서 1개 소비/재생성
4. 흡수 카운터가 분열 임계치 N=3 도달 시 분열 시작
5. 0.5초간 시각적으로 부풀음 → 자기 복제 1마리, 카운터 0
```

이 단계에선 동족/포식자 인식 없음. 세균은 영양분만 본다.

#### 2.4.2 2단계 — 사회성 + 위험감지 형질 (M2.2)

DNA 스키마 확장:
```
DNA.social = { sociability: -1 ~ 1 }   // 회피 ~ 무관심 ~ 군집
DNA.risk   = { boldness: 0 ~ 1 }        // 도주 ~ 무시 (포식자 인식)
```

행동 합성 (가중 벡터 합):
```
direction = w_n × dir(가장 가까운 영양분)
          + w_s × dir(가장 가까운 동료)   × sociability
          + w_r × dir(가장 가까운 백혈구) × -(1 - boldness)
```
가중치 초기값: `w_n=1.0, w_s=0.4, w_r=0.8` (조정 대상)

**호중구 영향**: 새 필드의 무영향 기본값 (`sociability=0, boldness=1`) 만 추가. 동작 변화 없음.

## 3. DNA 정본 스키마

### 3.1 식별된 불일치

| 표현 | 위치 | 크기 |
|---|---|---|
| DNA 객체 | 아이디어 기획서 본문 | 17 float |
| `#A34C-5F2E-81B0-0960` | UI 표시 | 8 byte (16 hex digit) |
| `DNA.segments[]` | 미니게임 | 10~15 정수 |

세 표현이 서로 매핑되지 않음.

### 3.2 채택안: **객체가 정본, 나머지는 파생**

```typescript
// 정본 (canonical): 게임 로직이 사용하는 유일한 DNA 표현
type DNA = {
  shape:    { base: number; w1: Wave; w2: Wave; w3: Wave };
  color:    { h: number; s: number; l: number };
  behavior: { target: number; speed: number; contact: number };
  meta:     { recovery: number; divide: number };
};
type Wave = { A: number; n: number; ω: number };
```

#### 파생 1: UI 코드 (해시 표현)

```typescript
function dnaToCode(dna: DNA): string {
  // 정보 손실 OK — 시각적 식별자 용도
  // 17개 float를 16개 nibble로 양자화 후 4-4-4-4 hex로 표현
  const nibbles = quantizeDNA(dna);  // 양자화 함수
  return formatHex(nibbles);  // "#A34C-5F2E-81B0-0960"
}
```

**원칙**: `dnaToCode`는 단방향. 코드에서 DNA 복원 불가(불필요).

## 4. 변이 전파 모델

### 4.1 식별된 어색함

> "장면 2의 결과는 장면 1의 모든 B세포에 동일 적용"

- 한 세포 감염이 즉시 전체로 점프 → 직관 위배
- 부분성공(`protectionRate`) 표현 어려움

### 4.2 채택안: **점진적 분열 전파**

```
감염 B세포 1개
  ↓ (DNA.meta.divide > 0 이므로 분열)
변이 B세포 2개 → 4개 → 8개 ...
  ↓ (시간 경과)
화면의 B세포 비율이 점진적으로 변이로 치환됨
```

- 부분성공: `protectionRate`에 비례하여 `meta.divide` 값을 낮춤 → 전파 속도 ↓
- 시각적 드라마: 점점 색이 바뀌는 군집
