# 배포 — GitHub Pages

> 정적 파일을 `gh-pages` 브랜치에 올리고 GitHub Pages 가 서빙하는 방식.
> GitHub Actions 도, Jekyll 도 사용 안 함.
>
> 라이브: https://goalgle.github.io/imm_simulator/

## 1. 한 줄 흐름

```
main (소스)
  ↓ npm run deploy   = npm run build + gh-pages -d dist
gh-pages (빌드 결과물만)
  ↓ GitHub Pages 자동 호스팅
https://goalgle.github.io/imm_simulator/
```

`main` 에는 소스코드만, `gh-pages` 에는 `dist/` 내용만. 둘이 완전히 분리.

## 2. 매번 배포 절차

```
npm run deploy
```

내부적으로:
1. `tsc && vite build` — 빌드 → `dist/index.html` + `dist/assets/index-*.js` 생성
2. `gh-pages -d dist` — 임시 worktree 에 dist 복사 + commit + `origin/gh-pages` 로 force push

## 3. 최초 셋업 (한 번만)

### 3.1 vite.config.ts — base path

```typescript
export default defineConfig({
  base: './',   // 서브패스 호스팅 (https://user.github.io/repo-name/) 대응
  ...
});
```

**왜 필요한가**: 기본값 `'/'` 면 빌드된 `index.html` 이 `src="/assets/index-*.js"` 절대 경로로 자산을 참조. GitHub Pages 가 `/repo-name/` 서브패스에 호스팅하면 `https://user.github.io/assets/...` 로 요청 → 404. `./` 면 상대 경로 (`./assets/...`) → 어느 서브패스든 동작.

### 3.2 gh-pages 패키지 + deploy 스크립트

```bash
npm install -D gh-pages
```

`package.json`:
```json
{
  "scripts": {
    "deploy": "npm run build && gh-pages -d dist"
  }
}
```

### 3.3 GitHub Pages 설정 (웹 UI)

저장소 → Settings → Pages:
- **Source**: `Deploy from a branch` ← GitHub Actions 아님, Jekyll 템플릿 무시
- **Branch**: `gh-pages` / `(root)`
- Save

`gh-pages` 브랜치는 첫 `npm run deploy` 가 자동으로 만들어 줌. 그 후 위 설정 가능.

### 3.4 git 인증 (HTTPS 리모트일 때)

기본 `git push` 가 username/password 를 묻고 거부당하면 (`fatal: could not read Username`), 다음 한 번이면 끝:

```bash
brew install gh                 # gh CLI 가 없으면
gh auth login                   # GitHub.com / HTTPS / Login with web browser
gh auth setup-git               # ← 핵심. git credential helper 셋업
```

**gh auth login 만으론 git 이 토큰을 못 씁니다.** `gh auth setup-git` 까지 해야 `git push` 와 `gh-pages` 패키지가 자동으로 GitHub 토큰을 사용.

확인:
```bash
git config --get credential.helper
# osxkeychain 또는 manager 등이 나오면 OK
```

## 4. 트러블슈팅

### 4.1 `fatal: could not read Username for 'https://github.com'`

git credential helper 가 설정 안 됐다. §3.4 절차 실행.

### 4.2 `fatal: a branch named 'gh-pages' already exists`

`gh-pages` 패키지의 stale 캐시. **push 가 한 번 실패하면 임시 worktree 가 정리 안 되고 남는 버그**가 있음. 다음 명령으로 정리 후 재시도:

```bash
rm -rf node_modules/.cache
git worktree prune
git worktree list   # 메인 worktree 하나만 보이면 OK
npm run deploy
```

### 4.3 `dist/` 가 빈 채로 push 됨

`vite.config.ts` 의 `base: './'` 가 빠졌거나, 빌드 전 변경이 안 commit 됐을 가능성. `npm run build` 후 `dist/index.html` 의 `<script src>` 가 `./assets/...` (상대) 인지 확인:

```bash
grep src dist/index.html
# <script type="module" crossorigin src="./assets/index-XXXX.js"></script>
```

`/assets/` (절대) 면 base 설정이 안 들어간 것.

### 4.4 배포 후 페이지 404

- 브랜치/폴더 설정 확인 (Settings → Pages 가 `gh-pages` / `(root)` 인지)
- Actions 탭에서 `pages-build-deployment` 워크플로 상태 (GitHub 가 내부적으로 돌리는 것)
- 1~2분 캐시 대기

### 4.5 자산이 깨져 (JS 로드 실패)

브라우저 DevTools Network 탭에서 어떤 경로로 요청하는지 확인. `https://user.github.io/assets/...` (서브패스 빠짐) 이면 §3.1 의 base 설정 확인.

## 5. 왜 이 방식인가

검토했던 대안:

| 방식 | 장점 | 단점 |
|---|---|---|
| **gh-pages 브랜치 (채택)** | 로컬에서 한 줄 (`npm run deploy`). 빌드 결과물이 git 트리 안에 안 들어감 | 초기 설정 (gh-pages 패키지, base 설정, git 인증) 필요 |
| GitHub Actions 자동 빌드 | `git push main` 만으로 자동 배포 | workflow yml 작성. 빌드 디버깅 어려움 |
| main/docs 폴더 | 가장 간단 | `dist/` 가 git 트리에 commit 됨 → main 히스토리 더러워짐. `docs/` 와 충돌 |

다른 호스팅 (Netlify/Vercel) 은 git 푸시만으로 자동 빌드해주는 게 매력적이지만, 현재는 GitHub 하나로 통일.

## 6. 함정 정리 — 다음에 헤매지 않기 위해

이번 셋업에서 시간 까먹은 지점들:

1. **루트 `index.html` 은 배포에 못 쓴다** — `<script src="/src/main.ts">` 로 TS 소스를 직접 참조하는 dev 전용. 배포에는 `dist/index.html` (빌드 결과물).
2. **`base: './'` 빠지면 서브패스에서 자산 다 깨짐** — 처음 한 번만 잡으면 영원.
3. **`dist/` 가 `.gitignore` 에 있어서 `git subtree push --prefix dist` 안 됨** — gh-pages 패키지가 이 문제를 우회 (임시 worktree 에서 force push).
4. **`gh auth login` 만으론 git 인증 안 됨** — `gh auth setup-git` 까지.
5. **gh-pages 패키지는 push 실패 후 stale worktree 남김** — `git worktree prune` 필요. §4.2.
6. **Jekyll 템플릿 선택 금지** — Settings → Pages 에서 Source 를 GitHub Actions 로 골랐을 때 추천되는 워크플로. Vite + TS 와 무관.

## 7. 코드 위치

- `vite.config.ts` — `base: './'`
- `package.json` — `scripts.deploy` + `devDependencies.gh-pages`
- 빌드 결과물 `dist/` — `.gitignore` 에 있음 (commit 대상 X)
