# 시스템 — 매 프레임 도는 9개

> `src/systems/*.ts`. 각 시스템의 책임·입출력·BloodScene 의 호출 순서.
> 엔티티 자체의 update 분기는 [엔티티.md](엔티티.md).

## 1. 호출 순서 (BloodScene.update)

```
[1] gameTime/dt 갱신
[2] cutscene 처리 (cutscene phase 면 ACTION 별 spawn/sim 진행)
[3] placing 처리 (placing phase 면 미리보기만)
[4] running 시뮬레이션:
    ├─ stage 시간/wave 갱신 + 결과 판정
    ├─ shockwave.update(t, dt)
    ├─ nutrient.update(t, dt)
    ├─ antibody.update(t, dt)
    ├─ separation (백혈구끼리, 세균끼리 각 1회)
    ├─ bacteriaBehavior.update(t, dt, ...)        ← drives + 분열 + 흡수
    ├─ whiteCellBehavior.update(t, dt, ...)       ← drives + 융합 + B세포 발사
    ├─ team.update(...)                            ← 영입/탈퇴/모드 결정
    ├─ contact.update(dt, ...)                     ← 접촉 데미지 + 처치 보상
    ├─ macrophage.update(t, dt, ...)               ← 시체 흡수 + 호중구 생산
    ├─ shockwave.applyToCells(...)                 ← 임펄스 적용
    ├─ 각 entity.update(t, dt, bounds)             ← LivingCell 자체 (살아있음/시체 분기)
    └─ 풍선(페이즈 2) 갱신 ([페이즈2.md](페이즈2.md))
[5] 매 프레임 끝: isAbsorbed=true 인 엔티티 청소 + HUD 갱신
```

## 2. 시스템 카탈로그

### 2.1 ShockwaveSystem

**책임**: 충격파 자원 (charges) + 활성 파동 풀 + 영향권 임펄스.

| 메서드                          | 입력       | 출력                               |
| ---------------------------- | -------- | -------------------------------- |
| `update(t, dt)`              | 가상 시간    | charges 충전 + 활성 파동 만료 처리         |
| `tryFire(x, y, t)`           | 발사점 + 시각 | charges 있으면 새 wave 추가, 없으면 false |
| `applyToCells(cells, t, dt)` | 대상 list  | 영향권 안 cell 에 임펄스 누적              |

**도메인 분리**: 순수 함수는 `src/domain/shockwave.ts` (`shockwaveRadius`, `shockwaveImpulse`, `isShockwaveAlive`). 단위 테스트 10 케이스.

**파라미터** (`BloodScene.SHOCKWAVE_CONFIG`):
- `maxCharges: 5`, `rechargeIntervalSec: 3`
- waveTemplate: `speed 280 px/s`, `duration 1.2 s`, `power 600 px/s²`, `bandwidth 50 px`

**충격파 영향 X**: 영양분, 시체 (`isDead()`), 대식세포.

### 2.2 NutrientSystem

**책임**: 영양분 풀 관리.

- 슬롯 수 고정 (40), 위치 무작위 (margin 40px 안쪽).
- 세균이 흡수 시 → 비활성 → 5초 후 다른 무작위 위치 부활.
- `consume(index)`: 한 영양분 비활성화 + 부활 timer 시작.
- 백혈구는 영양분과 통과만 (충돌 X).

도메인 단위 테스트 8 케이스 (`nutrientSystem.test.ts`).

### 2.3 AntibodySystem

**책임**: B세포 항체 (지뢰형 발사체) 풀.

- B세포가 `WhiteCellBehaviorSystem` 에서 `spawn(x, y, dirX, dirY, armament)` 호출.
- 매 프레임 `update(dt)`: 이동 거리 누적 → 사거리 도달 시 정지 (`vx=vy=0`).
- 세균이 영양분처럼 흡수 → `isAbsorbed=true` + 세균에 `applyDamage`.
- **정지 항체 누적 방지**: `maxStopped=5`. 초과 시 가장 오래된 것부터 FIFO 정리.

`AntibodyRenderer` 가 이동 중(보라 l60) / 정지(보라 l45) 두 색 분리 batch 렌더.

### 2.4 BacteriaBehaviorSystem

**책임**: 세균의 drives 평가 + 분열 처리 + 영양분/항체 흡수 분기.

매 프레임:
1. 각 세균의 `senses` 채움 (nearest predator, nearestNutrient or antibody, nearestAlly, commander)
2. `applyDriveLerp` 호출 — drives 합성 + turnRate 기반 lerp
3. nearestNutrient/Antibody 흡수 거리 도달 시 분기:
   - 영양분 → `nutrients.consume + registerAbsorb`
   - 항체 → `antibody.isAbsorbed=true + applyDamage(15)`
4. 흡수 카운터 3 도달 시 0.5s 부풀음 → 자식 spawn

**팀 멤버 분기**: 팀 모드 `aggressive` 면 `AGGRESSIVE_DRIVES` override (회피↓, seekPrey↑, followCommander 0). 커맨더는 자기 DNA 그대로.

### 2.5 WhiteCellBehaviorSystem

**책임**: 백혈구의 drives + 호중구 자기 융합 + B세포 발사 + 변이 분기.

- DNA 동등성 (`dna.kind === 'BCELL'`) 으로 분기:
  - BCELL: drives 무시. 매 프레임 `processBCellFiring` — fireCooldown 만료 시 시야 안 가장 가까운 세균에 발사
  - 그 외: `applyDriveLerp` + 호중구만 `processFusion`
- 변이 분기 (mutation 필드):
  - `zombie`: prey 후보 = 살아있는 호중구. 일반 호중구가 좀비를 추적 X (좀비만 호중구 추적)
  - `chaos`: prey 후보 = 살아있는 모든 LivingCell
  - `cancer`/`corruption`/`hyperactive`: 행동 정지 또는 scale 변화 (WhiteCell.updateAlive 자체에서 처리)
  - `paralysis`: cycle active 시 vx/vy=0 강제

**호중구 자기 융합** (`findAllyTarget` + `processFusion`):
- 자기 약함 (`hpRatio < WEAK_HP_THRESHOLD=0.5`) → 가장 가까운 강한 호중구 추적 (세균보다 우선)
- 자기 강함 + 약한 동료 있음 → 약한 동료 추적
- 거리 < `r1 + r2 + FUSION_PADDING(20)` 도달 시:
  - 약한 호중구 → `isAbsorbed=true` (시체 X, 즉시 소멸)
  - 강한 호중구 → `mergeCounter += 1`
  - mergeCounter ≥ 2 → 자기 isAbsorbed + 같은 자리에 SUPER spawn

좀비는 융합 후보에서 자동 제외 (mutation 필터).

### 2.6 ContactSystem

**책임**: 호중구↔세균 접촉 데미지 + 호중구 처치 시 세균 팀 보상 + T세포 영역 호중구 레벨업.

매 프레임:
1. `findContacts(whites, bacteria)` — 시체 자동 제외
2. 접촉 쌍마다:
   - 양쪽 hp 데미지 (`attack × dt`)
   - 양쪽 `applyCombatStimulus(contact)` — combat 시각 채널
3. 세균 사망 시:
   - 처치자가 NEUTROPHIL + T세포 영역 안 → `rewardNeutrophilLevelup` (level +1 + heal 30%)
4. 호중구 사망 시:
   - 데미지 가한 세균의 팀에 `registerAbsorb` (영양분 1개와 동등)

**변이 분기**:
- `zombie`: 호중구↔호중구 페어 추가 검사. 데미지 ×2 (호중구 vs)
- `chaos`: 호중구↔호중구 + 호중구↔세균 모두. 데미지 ×3

도메인 단위 테스트 6 케이스 (`contact.test.ts`).

### 2.7 TeamSystem

**책임**: 세균 팀 영입/탈퇴/해체 + 모드 결정.

매 프레임:
1. **영입**: 무소속 일반 세균이 어느 커맨더의 `commandRange` 안에 있고 팀이 max 미달이면 영입
2. **탈퇴**: 멤버가 커맨더로부터 `commandRange × 1.5` 이상 멀어지면 자동
3. **해체**: 커맨더 사망 시 팀 즉시 해체. `commanderDeathTimes` 에 시각 기록 (10초 뒤 진화 트리거)
4. **모드 결정** (`decideTeamModes`):
   - 멤버 < `baseTeamSize` → 강제 `defensive`
   - 시야(`visionRange`) 안 표적 + 팀 총 HP > 표적 HP × 1.5 → `aggressive` + `attackTarget`
   - 그 외 → `defensive`
5. **표적 우선순위**: BCELL > TCELL > NEUTROPHIL/SUPER/NK. 같은 우선순위 안에서 가장 가까운 것.

`consumeExpiredDeathRecords(currentTime)`: 사망 후 10초 경과한 record 반환 → `BloodScene.evolveCommanders` 가 일반 세균 1마리 무작위 커맨더로 변환.

### 2.8 MacrophageSystem

**책임**: 대식세포의 시체 추적/흡수 + 점수 누적 + 호중구 재생산.

- `cells`, `bacteria` 풀 받음. `isSettled()` 인 시체만 표적.
- 가장 가까운 시체의 X 좌표로 좌우 이동 (Y 고정).
- 흡수 거리 도달 시: `isAbsorbed=true` + 점수 누적 (세균 +10, 호중구 +20).
- 호중구 점수는 별도 (`whiteCellScoreInPool`) — 슈퍼 조건용.

**호중구 생산** (`tryProduceWhiteCell` — BloodScene 호출):
- `totalScore ≥ 100` 시 1마리 생산 + 점수 -100 (호중구 풀 0 리셋)
- 생산 종류:
  1. 1/10 확률 → NK_CELL
  2. 호중구 점수 ≥ 40 → NEUTROPHIL_SUPER
  3. 그 외 → NEUTROPHIL
- 생산 위치: 대식세포 정확한 위치에서 위로 솟구침 (vy=-180, ±40 무작위 vx)

**수동 조작** (Session 19): `← →` 키. `manualUntil = gameTime + MACROPHAGE_MANUAL_TIMEOUT(0.5)`. 만료 후 자동 모드 복귀.

### 2.9 분리력 (separation)

**책임**: 같은 종족끼리 너무 붙는 것 방지. **시스템 클래스 아님** — `src/domain/separation.ts` 의 순수 함수.

매 프레임 `applySeparation(cells, padding=4, strength=400)` 을 두 번 호출 (백혈구끼리, 세균끼리).

- 쌍별 검사. 거리 < `r1 + r2 + padding` 이면 멀어지는 가속도 누적.
- 다른 종족 간 분리는 ContactSystem 의 데미지가 대신 처리 (충돌 = 싸움).

도메인 단위 테스트 5 케이스 (`separation.test.ts`).

## 3. behaviorHelpers — applyDriveLerp

`src/systems/behaviorHelpers.ts` 의 공용 함수.

```typescript
function applyDriveLerp(cell, senses, dt) {
  const desired = computeDesiredDirection(cell.dna.drives, senses);
  const speed = cell.dna.behavior.speed * effectiveRatio;
  const desiredVx = desired.x * speed;
  const desiredVy = desired.y * speed;
  const factor = 1 - Math.exp(-cell.dna.behavior.turnRate * dt);
  cell.vx += (desiredVx - cell.vx) * factor;
  cell.vy += (desiredVy - cell.vy) * factor;
}
```

`BacteriaBehaviorSystem` 과 `WhiteCellBehaviorSystem` 둘 다 사용. drives 평가 + 관성 lerp 의 표준.

## 5. 이후 추가 동작 (위 섹션 보강분)

기존 섹션(2.x)에 더해진 동작들. 상세 전용 문서는 링크.

### 5.1 NK_CELL — 변이세포 우선 + 데미지 면역

`WhiteCellBehaviorSystem`:
- 감지 범위(`NK_MUTANT_DETECT_RANGE 200px`) 안에 **변이 호중구**(`mutation !== null`)가 있으면 커맨더보다 우선 추적 — `prey` override + `nearestCommander = null` (seekCommander 비활성, seekPrey 로 직진).
- 우선순위: (범위 내 변이 호중구) > (세균 커맨더 `seekCommander 1.5`) > (가장 가까운 일반 세균 fallback).

`ContactSystem` — NK 가 **커맨더 / 변이 호중구**를 잡을 때 NK 측 HP 소모 0 (암살자 톤):
- 호중구↔세균 페어: NK + `b.isCommander()` → NK 받는 데미지 0.
- 호중구↔호중구 페어: NK + 상대 변이 → NK 받는 데미지 0. 공격 트리거 조건도 확장 (NK + 변이 페어도 발생, 기존엔 zombie/chaos 만).

### 5.2 EntityRegistry — 컷신/디버그 제어

모든 종의 등장/표시/정지/속도/확률 5 dimension. `WhiteCellBehavior`/`BacteriaBehavior`/`Macrophage`/`Nutrient`/`Antibody` 가 매 프레임 조회 → 분기. 상세 [아키텍처.md §6](아키텍처.md).

### 5.3 특전(perk) 적용

- `WhiteCellBehavior`: 속도 `× speedMul` (매 프레임), 체력 `× hpMul` (spawn 시) — 호중구류만.
- `MacrophageSystem.consumeScoreForProduction`: 슈퍼 자격 `+ superBonus` 확률, NK 확률 `(0.1 + nkBonus)`.
- `populateStageStart`: T세포/B세포 `tcellCount/bcellCount` 자동 spawn.
- 매 프레임 `respawnDelayMul = nutrientRegenMul × (세균 동적 rule)`.
- 상세 [진행시스템.md](진행시스템.md).

### 5.4 사운드 trigger

- `BacteriaBehavior`: 분열 / 영양분 흡수.
- `WhiteCellBehavior`: 호중구 fusion.
- `TeamSystem`: defensive→aggressive 전환.
- `BloodScene`: 사망 검출(`notifyDeaths`) + 접촉 멜로디(`notifyContacts`).
- 상세 [사운드.md](사운드.md).

### 5.5 호중구 fusion 1대1 보장

`processFusion` — 약한 호중구는 `isFusing()` 검사로 한 strong 에게만 카운트. 한 weak 가 여러 strong 의 mergeCounter 를 올리던 버그 수정 (옆에 선 무관한 호중구는 영향 X).

### 5.6 MacrophageSystem 영역 분할

대식세포 N마리면 화면을 N등분 — 각자 자기 zone(`zoneMinX~zoneMaxX`) 안 시체만 추적. 매 프레임 x정렬 후 재할당. 점수(`productionCount` 포함)는 공유.
