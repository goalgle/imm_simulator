# 엔티티 — LivingCell 계층

> `src/entities/*.ts`. 추상 베이스 → 구체 종 → 시체 처리·변이 분기.
> 시스템(BehaviorSystem 등) 에서의 흐름은 [시스템.md](시스템.md).

## 1. 계층

```
LivingCell (추상)
  ├── WhiteCell    호중구 / NK / BCELL / TCELL / SUPER (DNA.kind 로 분기)
  └── Bacteria     일반 세균 + 커맨더

Macrophage         LivingCell 무관 — 시체 청소 전담
Antibody           단순 데이터 — B세포 발사체
Nutrient           단순 데이터 — 영양분
```

**왜 LivingCell?** 호중구·세균이 공유하는 게 너무 많았다 — vx/vy, hp, isAbsorbed, 시체 낙하, combat 시각, 등. 추상화로 100+ 줄 boilerplate 제거.

**왜 Macrophage 는 별도?** 시체와만 인터렉션. 충격파·접촉 모두 무시. drives 모두 0. LivingCell 의 update 사이클이 안 맞음 — 자기 update 로 분리.

## 2. LivingCell (추상 베이스)

`src/entities/LivingCell.ts`. 모든 살아있는 세포의 공통 동작.

### 2.1 보유 상태

```typescript
class LivingCell {
  vx = 0;
  vy = 0;
  protected combatResponse = 0;
  protected hp: number;
  isAbsorbed = false;        // 대식세포 흡수 표시. BloodScene 이 매 프레임 청소
  public dna: DNA;           // 인스턴스 (cloneDna). 변이 시 setDna 로 교체

  constructor(initialDna, renderer, x, y, phase, initialHp?) {
    this.dna = cloneDna(initialDna);
    this.handle = renderer.create(this.dna, x, y);
    this.handle.setPhase(phase);
    this.hp = initialHp ?? this.dna.combat.maxHp;
  }
}
```

### 2.2 공통 메서드

| 메서드 | 동작 |
|---|---|
| `applyDamage(amount)` | hp 감소 (0 최소) |
| `heal(amount)` | hp 회복 (maxHp 최대). 죽은 상태에선 회복 X |
| `hpRatio()` | hp / maxHp |
| `isDead()` | hp <= 0 |
| `isSettled()` | isDead && vx=0 && vy=0 (대식세포 흡수 대상) |
| `applyCombatStimulus(amount)` | combatResponse += amount (max 1). 시체는 무시 |
| `setPosition(x, y)` | 위치 + handle 동기화 |
| `setDna(dna)` | DNA 교체 + handle 갱신 (변이 시 호출) |
| `destroy()` | handle.destroy() |

### 2.3 update 분기

```typescript
update(t, dt, bounds) {
  if (this.isDead()) {
    this.updateAsCorpse(t, dt, bounds);
  } else {
    this.updateAlive(t, dt, bounds);   // 자식이 구현
  }
}
```

**자식 hook**:
- `updateAlive(t, dt, bounds)` — 추상. 살아있을 때 행동/물리/시각
- `onDeath()` — override. 사망 직후 정리 (예: Bacteria 의 분열 중단)

### 2.4 시체 처리 — updateAsCorpse

LivingCell 이 직접 처리:

```typescript
protected updateAsCorpse(t, dt, bounds) {
  this.onDeath();
  this.vx *= Math.exp(-CORPSE_HORIZONTAL_DAMPING(2.0) * dt);  // 옆 이동 감쇠
  this.vy += GRAVITY(80) * dt;                                 // 중력
  this.x += this.vx * dt;
  this.y += this.vy * dt;

  const floor = bounds.height - this.dna.shape.base * MIN_SCALE(0.5);
  if (this.y >= floor) {
    this.y = floor;
    this.vy = 0;
    this.vx = 0;                                                // 침전 → isSettled
  }

  this.handle.setScale(MIN_SCALE);
  this.handle.setVisualState({ shock: 0, combat: 0, life: 0 });
  // ...
}
```

**시체 특징**:
- 행동/충돌/임펄스 모두 정지 (BehaviorSystem 들이 isDead 자동 제외)
- 분리력에서 제외 → 겹침 허용
- 시각: 채도 0 (회색) + 떨림 정지 + MIN_SCALE(0.5)
- 화면 바닥에서 침전 → 대식세포 흡수 대상

### 2.5 살아있을 때 시각 헬퍼 — applyAliveVisuals

자식이 `updateAlive` 끝에 호출. combat 감쇠 + 시각 통보를 표준화:

```typescript
protected applyAliveVisuals(t, dt, options) {
  this.combatResponse *= Math.exp(-COMBAT_RECOVERY(4.0) * dt);
  if (this.combatResponse < 0.001) this.combatResponse = 0;

  const hpScale = MIN_SCALE + (1 - MIN_SCALE) * this.hpRatio();
  const finalScale = hpScale * (options.scaleExtra ?? 1);
  this.handle.setScale(finalScale);
  this.handle.setVisualState({
    shock: options.shock ?? 0,
    combat: this.combatResponse,
    life: 1,
  });
  this.handle.setPosition(this.x, this.y);
  this.handle.update(t);
}
```

`scaleExtra` 는 분열 펄스 같은 추가 배율. `shock` 은 호중구의 충격파 시각 채널.

## 3. WhiteCell

`src/entities/WhiteCell.ts`. 호중구·NK·BCELL·TCELL·SUPER 를 모두 담당. dnaKind 로 행동 분기.

### 3.1 추가 상태

```typescript
class WhiteCell extends LivingCell {
  private shockResponse = 0;                  // 충격파 시각 채널 (지수 감쇠)
  mutation: MutationKind | null = null;       // 변이 라벨

  // 호중구 자기 융합
  mergeCounter = 0;                           // 약한 동료 흡수 카운트 (2 → SUPER)
  fusionAnim: { ... } | null = null;          // 빨려들어감 애니메이션

  // T세포 영역에서 호중구 진화
  level = 0;                                  // NEUTROPHIL 만. 5 → 진화

  // B세포 발사
  fireCooldownRemaining = 0;                  // BCELL 만

  // 변이별 mode timer (gameTime 기준)
  cancerSpawnTime: number | null = null;      // cancer 6s 후 분열
  cancerDivideRequested = false;              // BehaviorSystem 처리 후 false
  corruptionStartTime: number | null = null;  // 5s 점감
  pendingCorruptionTrigger = false;           // scale 0 도달 시 true
  hyperactiveStartTime: number | null = null; // 4s 점증
  pendingHyperactiveExplosion = false;        // scale max 도달 시 true
  paralysisStartTime: number | null = null;   // 3s cycle (변이 호중구)
  paralyzedUntil = 0;                         // 외부 전파 받은 호중구 (gameTime 기준)
}
```

### 3.2 마찰 + 경계 반사

호중구만의 물리. 충격파 임펄스가 마찰로 자연히 잦아들고, 벽에 부딪치면 일부 반사:

```typescript
const FRICTION = 1.5;        // 1/sec 지수 감쇠
const WALL_BOUNCE = 0.5;     // 0=흡수, 1=완전 탄성
const SHOCK_RECOVERY = 3.0;  // shockResponse 회복 속도
```

### 3.3 자기 융합 임계

```typescript
export const WEAK_HP_THRESHOLD = 0.50;   // 이 이하면 "약함"
const FUSION_ANIM_DURATION = 0.35;       // 빨려들어감 시간
const FUSION_SHRINK = 0.85;              // 흡수되며 축소 배율
const FUSION_FADE = 0.7;                 // 흡수되며 페이드 알파
```

### 3.4 변이 모드 — updateAlive 분기

`updateAlive` 안에서 `mutation` 으로 분기:

| mutation | 동작 |
|---|---|
| `null` | 일반 호중구 (또는 다른 dnaKind) 동작 |
| `'cancer'` | 행동 정지 + GRAVITY 80 으로 즉시 낙하. cancerSpawnTime 도달 시 분열 요청 플래그 |
| `'corruption'` | elapsed = t - corruptionStartTime. scale = 1 − elapsed/5. scale 0 도달 시 트리거 |
| `'hyperactive'` | scale = 1 + 1.5 × (elapsed/4). 임계 도달 시 폭발 트리거 |
| `'paralysis'` | cycle = (t - paralysisStartTime) % 3. cycle < 0.5 면 마비 (vx/vy=0). 외부에서 paralyzedUntil 도 검사 |
| `'zombie'` / `'chaos'` | 시각만 변경됨 (dna). 행동은 BehaviorSystem 의 prey 후보 변경 |

**변이 메커니즘 핵심**: dna 는 시각·기본 형질만 바꾸고, "정지/낙하/timer/폭발" 같은 행동은 entity·시스템 분기로. dna 만으론 표현 불가능한 것들.

### 3.5 라이프사이클

```typescript
class WhiteCell {
  setMutation(kind);           // mutation 라벨 갱신
  beginCancerDivide(t);        // setMutation('cancer') 후 호출. cancerSpawnTime = t + 6
  beginCorruption(t);          // corruptionStartTime = t
  beginHyperactive(t);         // hyperactiveStartTime = t
  beginParalysis(t);           // paralysisStartTime = t
}
```

`BloodScene.finalizeWave` 가 변이 적용 시 `setDna + setMutation + begin*` 호출.

## 4. Bacteria

`src/entities/Bacteria.ts`. 일반 세균 + 커맨더. dnaKind 로 분기.

### 4.1 추가 상태

```typescript
class Bacteria extends LivingCell {
  // 분열 (일반 세균)
  absorbCounter = 0;             // 영양분 누적 (3 → 분열)
  divideTimer = 0;               // 0.5s 부풀음 진행

  // 커맨더 전용
  level = 0;
  totalAbsorbed = 0;             // 영양분 흡수 누계 (커맨더의 레벨업 기준)
  currentVisionRange: number;    // 흡수 시 dna.command.visionGrowth 만큼 ↑
  currentCommandRange: number;
}
```

### 4.2 분열 (일반 세균)

```typescript
registerAbsorb() {
  if (커맨더) {
    this.totalAbsorbed += 1;
    this.currentVisionRange  += dna.command.visionGrowth;
    this.currentCommandRange += dna.command.commandGrowth;
    if (totalAbsorbed % dna.command.levelUpAbsorbCount === 0) {
      this.level += 1;
    }
    // 분열 X
  } else {
    this.absorbCounter += 1;
    if (absorbCounter >= 3) {
      this.beginDivision();  // 0.5s 부풀음 → BacteriaBehaviorSystem 이 자식 spawn
    }
  }
}
```

분열 자식은 부모와 같은 DNA preset 으로 새 cell. 부모 absorbCounter 0 리셋.

### 4.3 isCommander / currentMaxTeamSize

```typescript
isCommander() {
  return this.dna.command.baseTeamSize >= 1;
}

currentMaxTeamSize() {
  return baseTeamSize + Math.floor(level / teamSizeStep);
}
```

### 4.4 onDeath override

```typescript
protected onDeath() {
  this.divideTimer = 0;        // 분열 중단
  this.beginDivisionRequested = false;
}
```

부풀음 중에 죽으면 분열 안 일어남.

## 5. Macrophage

`src/entities/Macrophage.ts`. LivingCell 무관 — 별도 클래스.

### 5.1 위치

- Y 고정 (`bounds.height - r`).
- X 만 이동. `MacrophageSystem` 이 가장 가까운 시체로 추격.

### 5.2 미인터렉션

- 충격파 영향 X — 정해진 동선
- 살아있는 세포 충돌 X — drives 모두 0
- 시체만 처리 (`isSettled` 인 LivingCell 만)

### 5.3 시각

- base 13, `setScale(1, 0.55)` 로 납작
- 초록 (`hsl 120, 30%, 50%`)

## 8. 새 종족 추가 시

대부분의 경우 새 클래스는 필요 없다. WhiteCell/Bacteria 가 dnaKind 분기로 흡수 가능.

새 클래스가 필요한 경우:
- update 사이클이 완전히 다름 (Macrophage 처럼)
- LivingCell 의 시체 처리가 안 맞음
- 자체적인 추가 상태 필드가 많음

지침:
1. `LivingCell` extends + `updateAlive` 구현
2. 종족 고유 형질 (마찰/반사/timer 등)
3. `onDeath()` override (필요 시)
4. BloodScene 에서 해당 BehaviorSystem 에 등록 (또는 새 시스템)
