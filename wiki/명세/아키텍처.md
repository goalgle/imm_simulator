## 2. 레이어

의존성은 안쪽을 향한다.

```
scenes/      (Phaser 진입 — BloodScene)
  ↓ uses
systems/     (per-frame 로직, 여러 엔티티에 걸침)
  ↓ uses
entities/    (게임 오브젝트, Phaser 의존 OK)
  ↓ uses
render/      (렌더 어댑터)
  ↓ uses
domain/      (순수 로직, Phaser 의존 0)
```

| 디렉토리 | 책임 | Phaser? |
|---|---|---|
| `src/domain/` | 순수 함수·타입. DNA, 수학, 충돌 판정 | ❌ 금지 |
| `src/entities/` | 게임 오브젝트 (LivingCell 등). 상태 보유 | ⭕ OK |
| `src/render/` | 렌더 어댑터. CellRenderer 인터페이스 + 구현 | ⭕ OK |
| `src/systems/` | 매 프레임 도는 시스템 | ⭕ OK |
| `src/scenes/` | Phaser Scene. 단일 BloodScene | ⭕ |
| `src/stages/` | 스테이지 config 타입 | ❌ |
| `src/cutscenes/` | 컷신 대본 + step 타입 | ❌ |

**`src/domain/` 의 Phaser 금지** 가 강제하는 것:
- 도메인 단위 테스트 가능 (Vitest)
- 렌더러 교체 가능 (Graphics → SDF 라도 도메인 코드는 무수정)

## 3. 렌더 어댑터

`src/render/CellRenderer.ts` 는 인터페이스만 정의:

```typescript
interface CellRenderHandle {
  setPosition(x, y);
  setPhase(phase);
  setScale(scaleX, scaleY?);
  setAlpha(alpha);
  setVisualState({ shock, combat, life });
  setDna(dna);
  update(t);
  destroy();
}

interface CellRenderer {
  create(dna, x, y): CellRenderHandle;
}
```

**현재 구현체**: `GraphicsCellRenderer` (`per-cell Phaser.Graphics + fillPoints 매 프레임 redraw`).

**선택 근거** (`docs/시스템.md §1.2 M0 검증`):
- 5000개 / 64 verts / 60fps 확인 (Apple Silicon)
- CPU-bound 워크로드 — GPU/색 batch 영향 미미
- B (Mesh) 대비 단순성. D (SDF) 는 한계 도달 시 어댑터 교체로 대응

엔티티(`LivingCell` 등)는 `CellRenderer` / `CellRenderHandle` 만 의존. 렌더러 교체 시 엔티티 코드는 무수정.

### 3.1 시각 자극 — 3 채널 합성

`VisualState = { shock, combat, life }` 를 매 프레임 엔티티가 통보. 렌더러가 내부에서 합성:

```
hue   = baseH + (RED - baseH) × combat × 0.6
sat   = (baseS + 15·shock + 20·combat) × life
light = baseL − 25·shock
amp   = (1 + 0.5·shock + 0.4·combat) × life
```

새 자극이 추가되면 채널만 늘리지, 렌더 분기를 ad-hoc 으로 두지 않는다.

### 3.2 렌더 스타일 — TYPE A/B/C

`GraphicsCellRenderer.ts` 상단 `RENDERER_TYPE: 'A' | 'B' | 'C'` 상수로 토글.

| TYPE | 톤 |
|---|---|
| A | 매끈한 구체 음영 (의학 일러스트, 기본) |
| B | 발광/젖은 (네온 생체) |
| C | 만화풍 외곽선 + 평면 톤 |

영웅급 (`isHeroDna`: 커맨더 / T세포 / 슈퍼호중구) 에는 PostFX `addGlow` 가 추가됨.

## 4. 가상 시간

**`BloodScene.gameTime` 이 정본 시계**. Phaser 의 `this.time.now` 무시.

```typescript
override update(_time, delta) {
  if (paused) { ... return; }
  const dtReal = delta / 1000;
  const dt = dtReal * this.speedMultiplier;  // 1× / 2× / 4×
  this.gameTime += dt;
  const t = this.gameTime;
  // 모든 시스템에 t, dt 명시 전달
}
```

| 상수 | 의미 |
|---|---|
| `gameTime` | 가상 시간 (초). 빨리감기 영향 받음 |
| `speedMultiplier` | 1 / 2 / 4 |
| `paused` | `[P]` 토글. true 면 update 무시 |

**일관성 원칙**: 모든 시간 기반 로직은 `gameTime` 사용. `pointerdown` 핸들러도 `gameTime` 으로 충격파 발사 시각 기록. 두 시계를 섞으면 빨리감기에서 메커닉 깨짐.

**상한**: 4× 까지 안전 (호중구 max 이동 거리 `30 × 0.067 ≈ 2px` < 충돌 반경). 8×+ 는 substep 필요 — 현재 미구현.

**가속 영향 X**: FPS 측정, 키 입력, HUD 갱신 (모두 실시간).

## 5. 단계 머신 — BloodScene.phase

```
cutscene (인트로 대본)
   ↓ end()
placing (T세포 / 세균커맨더 / B세포 배치)
   ↓ 큐 비면
running (정상 시뮬레이션)
```

| phase | sim 진행 | 화면 |
|---|---|---|
| `cutscene` | ACTION 별 (sim 정지 또는 진행) | 텍스트 박스 + 단어별 타이핑 |
| `placing` | 정지 | 마우스 따라 미리보기 셰입 |
| `running` | 진행 | 정상 |

추가로 스테이지 평가 상태:

| stageState | 의미 |
|---|---|
| `running` | 카운트다운 + 판정 검사 |
| `resolved` | 결과 모달. sim 정지 |

페이즈 2 (호중구 내부) 는 **단계가 아니라 풍선 레이어** — `running` 중에 별도로 떠 있음. [페이즈2.md](페이즈2.md) 참조.

### 5.1 컷신 / 스테이지 런너

`cutscene` phase 는 **선언적 step 시퀀스**를 해석한다 (`CutsceneStep[]`). 같은 런너가 두 곳에서 재사용:
- **글로벌 인트로** (`cutscenes/intro-script.ts`, `CUTSCENE_INTRO`) — 게임 첫 진입 1회.
- **스테이지 intro** (`stages/all.ts` 의 `StageConfig.intro`) — 매 스테이지 진입.

step 종류: `narration` / `warning` / `control` / `spawn` / `place` / `pause` / `waitFor` / `waitForShockwaves` / `waitForBacteriaKilled` / `waitForMacrophageProductions` / `evolveCommander` / `nutrientRegen` / `clear` / `end`. 작성법은 [docs/스크립트.md](../../docs/스크립트.md).

전체 흐름:
```
첫 진입 → CUTSCENE_INTRO ([S]/[ESC] 스킵)
  ↓ end / 스킵
STAGE 타이틀 (2.5s tween) → stage.intro 런너
  ↓
placing (place() 큐 — 사용자 클릭 배치)
  ↓ 큐 비면
running: setup 일괄 실행 → waves 시간 흐름 → endConditions 검사
  ↓ clear / wipe / timeout
결과 모달 (키 + 버튼)
  ↓ 다음 스테이지        ↓ 재시작
특전 선택 (카드 3장)    scene.restart(같은 stage)
  ↓ applyPerk + addStageSkillCharges
scene.restart(다음 stage, skipIntro)
```

`endCutscene` 의 핵심: phase 가 `cutscene` 인 채 머무는 동안 매 프레임 재호출되지 않도록 `cutsceneSteps=[]` sentinel + `applyCutsceneClear()` (entity 정리) 후 stage flow.

### 5.2 스테이지 시스템

`stages/types.ts` 의 `StageConfig`: `id` / `title` / `intro` / `setup` / `waves` / `timeLimit` / `endConditions` / `stars`. `stages/all.ts` 에 STAGE_1~10 + `STAGES` 배열. `setup`/`waves` 의 step 은 `runStageStep` 이 즉시 실행 (timer 없음 — narration/pause/waitFor 무시). 작성법은 [docs/스크립트.md](../../docs/스크립트.md).

### 5.3 모바일 대응

- `effectiveHeight() = scale.height − (모바일 URL바 80) − (스킬 바 64)`. 모든 게임 좌표 기준.
- `?mobile`/`?portrait`: 디버그 텍스트 OFF, 세로 swipe 로 속도 변경, 결과/특전/스킬 모두 버튼.
- CSS `100dvh` (index.html) + `BOTTOM_RESERVE_MOBILE` 이중 안전장치 (iOS Safari URL 바).

## 6. EntityRegistry — 컷신·디버그 제어 (단계 1~6, 2026-05-21)

모든 개체 종류의 **등장·표시·정지·속도·확률**을 통일된 인터페이스로 제어. `src/domain/entityControl.ts`.

```typescript
type EntityKind =
  | 'nutrient' | 'bacteria' | 'bacteriaCommander'
  | 'neutrophil' | 'neutrophilSuper' | 'nk' | 'bcell' | 'tcell'
  | 'macrophage' | 'antibody' | 'bubble';

type EntityControl = {
  enabled: boolean;     // 새 spawn 막기 (이미 있는 건 별개)
  visible: boolean;     // 화면 표시 (handle.setVisible)
  frozen: boolean;      // 행동 정지 — 모든 시스템 분기
  speedMul: number;     // 속도 배수 — 움직이는 개체만
  spawnProb: number;    // 등장 확률 — 확률 분기 있는 종류만 (NK 1/10, T세포 진화 1/3 등)
};

class EntityRegistry {
  reset(): void;                                          // 모든 종 디폴트로
  set(kind, partial: Partial<EntityControl>): void;       // 부분 갱신
  setMany(kinds, partial): void;                          // 여러 종 일괄
  get(kind): EntityControl;
}
```

**디폴트**: 모든 종 `{ enabled: true, visible: true, frozen: false, speedMul: 1, spawnProb: 1 }`.

**적용 위치**:
- `BloodScene` 이 인스턴스 보유, 모든 시스템 생성자에 주입
- 각 시스템 매 프레임 조회하여 분기 (spawn 차단, 행동 정지, 속도 배수, 확률 곱셈, visible 토글)
- 컷신 종료 시 `reset()` 으로 모든 변경 해제
- 컷신 step 의 `control('xxx', { ... })` 가 set 호출

DnaKind ↔ EntityKind 매핑은 `dnaKindToEntityKind(kind)` 헬퍼.

## 8. 새 종족 추가 가이드

1. `src/domain/dna.ts` 에 새 프리셋 (DNA 객체). `DnaKind` 유니온에 라벨 추가.
2. (필요 시) `src/entities/` 에 새 클래스 — `LivingCell` extends, `updateAlive` 구현. 단순 종이면 기존 클래스 재사용.
3. (필요 시) 종족별 BehaviorSystem 또는 기존 시스템 확장.
4. `BloodScene` 에서 인스턴스 생성 + 적절한 시스템에 등록.

이전엔 100+ 줄 boilerplate 복사가 필요했다. 현재는 종족 고유 로직만 작성.
