## 2. 레이어

의존성은 안쪽을 향한다.

```
scenes/      (Phaser 진입 — BloodScene)
  ↓ uses
systems/     (per-frame 로직, 여러 엔티티에 걸침)
  ↓ uses
entities/    (게임 오브젝트, Phaser 의존 OK)
  ↓ uses
render/      (렌더 어댑터)
  ↓ uses
domain/      (순수 로직, Phaser 의존 0)
```

| 디렉토리 | 책임 | Phaser? |
|---|---|---|
| `src/domain/` | 순수 함수·타입. DNA, 수학, 충돌 판정 | ❌ 금지 |
| `src/entities/` | 게임 오브젝트 (LivingCell 등). 상태 보유 | ⭕ OK |
| `src/render/` | 렌더 어댑터. CellRenderer 인터페이스 + 구현 | ⭕ OK |
| `src/systems/` | 매 프레임 도는 시스템 | ⭕ OK |
| `src/scenes/` | Phaser Scene. 단일 BloodScene | ⭕ |
| `src/stages/` | 스테이지 config 타입 | ❌ |
| `src/cutscenes/` | 컷신 대본 + step 타입 | ❌ |

**`src/domain/` 의 Phaser 금지** 가 강제하는 것:
- 도메인 단위 테스트 가능 (Vitest)
- 렌더러 교체 가능 (Graphics → SDF 라도 도메인 코드는 무수정)

## 3. 렌더 어댑터

`src/render/CellRenderer.ts` 는 인터페이스만 정의:

```typescript
interface CellRenderHandle {
  setPosition(x, y);
  setPhase(phase);
  setScale(scaleX, scaleY?);
  setAlpha(alpha);
  setVisualState({ shock, combat, life });
  setDna(dna);
  update(t);
  destroy();
}

interface CellRenderer {
  create(dna, x, y): CellRenderHandle;
}
```

**현재 구현체**: `GraphicsCellRenderer` (`per-cell Phaser.Graphics + fillPoints 매 프레임 redraw`).

**선택 근거** (`docs/시스템.md §1.2 M0 검증`):
- 5000개 / 64 verts / 60fps 확인 (Apple Silicon)
- CPU-bound 워크로드 — GPU/색 batch 영향 미미
- B (Mesh) 대비 단순성. D (SDF) 는 한계 도달 시 어댑터 교체로 대응

엔티티(`LivingCell` 등)는 `CellRenderer` / `CellRenderHandle` 만 의존. 렌더러 교체 시 엔티티 코드는 무수정.

### 3.1 시각 자극 — 3 채널 합성

`VisualState = { shock, combat, life }` 를 매 프레임 엔티티가 통보. 렌더러가 내부에서 합성:

```
hue   = baseH + (RED - baseH) × combat × 0.6
sat   = (baseS + 15·shock + 20·combat) × life
light = baseL − 25·shock
amp   = (1 + 0.5·shock + 0.4·combat) × life
```

새 자극이 추가되면 채널만 늘리지, 렌더 분기를 ad-hoc 으로 두지 않는다.

### 3.2 렌더 스타일 — TYPE A/B/C

`GraphicsCellRenderer.ts` 상단 `RENDERER_TYPE: 'A' | 'B' | 'C'` 상수로 토글.

| TYPE | 톤 |
|---|---|
| A | 매끈한 구체 음영 (의학 일러스트, 기본) |
| B | 발광/젖은 (네온 생체) |
| C | 만화풍 외곽선 + 평면 톤 |

영웅급 (`isHeroDna`: 커맨더 / T세포 / 슈퍼호중구) 에는 PostFX `addGlow` 가 추가됨.

## 4. 가상 시간

**`BloodScene.gameTime` 이 정본 시계**. Phaser 의 `this.time.now` 무시.

```typescript
override update(_time, delta) {
  if (paused) { ... return; }
  const dtReal = delta / 1000;
  const dt = dtReal * this.speedMultiplier;  // 1× / 2× / 4×
  this.gameTime += dt;
  const t = this.gameTime;
  // 모든 시스템에 t, dt 명시 전달
}
```

| 상수 | 의미 |
|---|---|
| `gameTime` | 가상 시간 (초). 빨리감기 영향 받음 |
| `speedMultiplier` | 1 / 2 / 4 |
| `paused` | `[P]` 토글. true 면 update 무시 |

**일관성 원칙**: 모든 시간 기반 로직은 `gameTime` 사용. `pointerdown` 핸들러도 `gameTime` 으로 충격파 발사 시각 기록. 두 시계를 섞으면 빨리감기에서 메커닉 깨짐.

**상한**: 4× 까지 안전 (호중구 max 이동 거리 `30 × 0.067 ≈ 2px` < 충돌 반경). 8×+ 는 substep 필요 — 현재 미구현.

**가속 영향 X**: FPS 측정, 키 입력, HUD 갱신 (모두 실시간).

## 5. 단계 머신 — BloodScene.phase

```
cutscene (인트로 대본)
   ↓ end()
placing (T세포 / 세균커맨더 / B세포 배치)
   ↓ 큐 비면
running (정상 시뮬레이션)
```

| phase | sim 진행 | 화면 |
|---|---|---|
| `cutscene` | ACTION 별 (sim 정지 또는 진행) | 텍스트 박스 + 단어별 타이핑 |
| `placing` | 정지 | 마우스 따라 미리보기 셰입 |
| `running` | 진행 | 정상 |

추가로 스테이지 평가 상태:

| stageState | 의미 |
|---|---|
| `running` | 카운트다운 + 판정 검사 |
| `resolved` | 결과 모달. sim 정지 |

페이즈 2 (호중구 내부) 는 **단계가 아니라 풍선 레이어** — `running` 중에 별도로 떠 있음. [페이즈2.md](페이즈2.md) 참조.

## 7. 새 종족 추가 가이드

1. `src/domain/dna.ts` 에 새 프리셋 (DNA 객체). `DnaKind` 유니온에 라벨 추가.
2. (필요 시) `src/entities/` 에 새 클래스 — `LivingCell` extends, `updateAlive` 구현. 단순 종이면 기존 클래스 재사용.
3. (필요 시) 종족별 BehaviorSystem 또는 기존 시스템 확장.
4. `BloodScene` 에서 인스턴스 생성 + 적절한 시스템에 등록.

이전엔 100+ 줄 boilerplate 복사가 필요했다. 현재는 종족 고유 로직만 작성.
